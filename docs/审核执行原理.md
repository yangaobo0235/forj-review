# 审核执行原理

## 输入和任务生命周期

扩展读取业务页面字段和图片 URL，通过 `POST /api/review/jobs/urls` 一次提交，服务立即排队识别并自动关闭材料提交阶段。普通图片不下载到本地、不裁剪、不上传正文；模型直接读取原图 URL，语义重读仍使用同一原图地址。

```text
页面身份与采集清单 → 字段、材料 URL
  → 公平模型队列 → 材料分类、专属提取与受控重读
  → 复用 RecognitionBatchResult → 统一审核主图
  → 完整性、外部核验、字段比较、业务规则
  → 事实与降级汇总 → 有序任务及审核建议
  → 扩展展示证据 → 人工处理与受控页面动作
```

二维码优先复用模型提取的 `qr_codes`。没有可靠结果时，仅在受控候选图片上做一次内存读取，先 ZXing 后 OpenCV，不写盘、不上传，再核验官网域名、HTTPS、访问和字段。二维码官网核验仅检查二维码可读取、网址属于允许的商务部官网，以及官网可访问并提取到回收证明编号和车架号；三步成功即通过。提取值继续作为官网证据参与证明编号、车架号的统一字段比对，差异由对应字段报告，不改变二维码官网核验结果。

| API | 用途 |
| --- | --- |
| `POST /api/review/jobs/urls` | 扩展正常任务入口 |
| `GET /api/review/jobs/{job_id}` | 状态、进度、部分或最终结果 |
| `DELETE /api/review/jobs/{job_id}` | 有界取消排队与运行任务 |
| `POST /api/review/jobs` | 同样使用公平队列的 URL 提交入口 |
| `POST /api/review/assist` | 保留的同步调用接口 |

单次最多 16 张图，图片 ID 和序号分别唯一。HTTP(S) URL 的签名参数原样保留，采集错误明确记录。扩展约每秒轮询，最多等待 120 秒；单次创建和查询请求另有 15 秒限制。取消、重置、卸载及业务切换后丢弃旧任务迟到响应。

任务 `status` 为 `RUNNING / PARTIAL / COMPLETED / FAILED / CANCELLED`，阶段 `phase` 为 `PREPARING / RECOGNIZING / FINALIZING / COMPLETED / FAILED / CANCELLED`。`PARTIAL` 是终态，可同时为 `phase=COMPLETED`。进度记录总数、提交数、成功数、失败数和超时数；没有执行过的阶段不能伪造为完成。

审核 URL、结果、状态和进度仅在内存保留约十分钟。进程重启即丢失；取消终结任务保留原结果。配置会话和页面版本属于另一条持久化链路，保存于 PostgreSQL。

生产 Compose 的模型全局/单任务并发为 16/8，最终汇总并发为 2；队列按任务轮转防止某一任务长期占满。最终汇总复用已识别批次，不再次调用图片模型。具体值可由运维配置覆盖。

## 通用主图与业务能力

主图入口为 `src/forj_review_service/runtime/workflow/graph.py`，所有业务共用，页面和政策由 Profile 决定：

```text
resolve_context → validate_input
  → assess_coverage → plan_input_capabilities → execute_input_capabilities
  → extract_evidence → assess_evidence_quality → plan_capabilities
  → execute_evidence_validation → execute_evidence_capabilities → execute_pre_compare
  → compare_fields → execute_post_compare → execute_final_review
  → assemble_facts → record_degradation → prepare_review_tasks
  → derive_recommendation → build_response
```

输入错误直接进入错误响应，不执行后续能力。URL 任务在进入最终主图前已完成识别，此时提取节点复用批次；不能误认为主图的输入阶段能够撤销之前发生的模型调用。

| 能力阶段 | 用途 |
| --- | --- |
| `INPUT_COVERAGE` | 采集和输入检查 |
| `EVIDENCE_VALIDATION` | 识别后的完整性、页码和证据检查 |
| `EVIDENCE` | 外部核验与证据补全 |
| `PRE_COMPARE` | 字段比较之前的事实准备 |
| `POST_COMPARE` | 消费比较结果，执行日期、车型等规则 |
| `FINAL_REVIEW` | 消费前序检查和事实，执行最终复核 |

阶段和事实依赖共同决定执行顺序。同一能力一次审核只执行一次，各阶段结果累积；缺某张材料不阻止所有不依赖它的能力。超时、重试、依赖阻塞和失败策略由注册能力统一处理。

只有成功能力实际返回且在 `output_facts` 声明的字段进入证据集合，来源固定为 `capability` 与能力 ID，不能伪装成页面或图片。字段比较需要的事实必须在比较前产出，后置阶段不能补证据后沿用旧比较。中间节点维护独立状态，只有最终或错误分支构造公开响应；部分进度可独立生成快照，不等于最终规则已经执行。

## 上传事实与证据完整性

`businesses/material_presence.py` 判断材料是否上传，支持组间任选、组内全部提供。材料类型或身份证面别已可靠确认时，字段识别失败不抹除上传事实；类型不明时保留待确认。

`businesses/completeness.py` 判断实际材料的页码、字段来源和识别质量。上传齐全不等于证据齐全，两者分开保留；业务具体要求见[业务规则](业务/)。二选一的证据要求通过替代组声明，不能把两项独立必传或 `minimum_count=0` 当作二选一。

## 判断语义

| 结果 | 判定边界 |
| --- | --- |
| `CONFLICT` 红色 | 可靠、可比较的证据证明差异，或明确违反硬性规则 |
| `INSUFFICIENT` 橙色 | 证据不足、不确定、缺权威来源、外部不可用或明确交人工 |
| `MATCH` 绿色 | 当前字段要求的证据和检查满足规则 |

先看可靠证据能否证明冲突，再看不确定性和完整性，最后才允许通过。额外不确定材料不能掩盖已有可靠冲突；不确定读值本身也不能证明冲突或一致。存在多个候选控件时，没有可信页面值，不能用它证明冲突。政策人工例外保持人工复核，不擅自变成硬性否决。

整单 `REVIEW_REQUIRED` 表示需要人工处理，任何阻断项或待确认项都不能被其他绿色字段抵消。系统不按置信度平均、加权评分或多数投票得出通过。`SYSTEM` 字段只检查页面输入，不宣称完成材料核验。

稳定 `reason_codes` 包括 `VALUE_MISMATCH`、`RULE_VIOLATION`、`EVIDENCE_MISSING`、`RECOGNITION_UNCERTAIN`、`AUTHORITY_MISSING`、`PAGE_VALUE_MISSING`、`POLICY_REVIEW`、`EXTERNAL_UNAVAILABLE`、`SYSTEM_INPUT`。前端不能解析理由文本重新判定。

## 证据比较和来源

标准字段按业务分区组织，例如 `old_vehicle.*`、`new_vehicle.*`、`transfer_invoice.*`。字段策略限定允许的材料、归一化方式、比较片段及是否需要多类材料互证。普通多来源字段可以声明允许单一证据；明确要求互证时，只有一个来源应转待复核。

权威链的链首是唯一基准，其余来源按声明的全值或后八位窗口与其比较。缺可靠链首时待复核，不能让位给后续来源；链首有多个可靠不同值时冲突。车源普通行驶证字段以行驶证为基准，不从辅助材料代读。

相同材料按来源、材料身份和规范化字段值去重；相同值保留可定位的代表证据并合并不确定/重读标记，不同值全部保留。不能用页面待审核值挑选材料候选，也不能用重复读取绕过不确定保护。置信度用于展示和代表证据选择，不替代裁决规则。

差异高亮以页面原始值为展示基准，与权威链结论基准不同。后端生成规范化比较片段及偏移，再映射回原值范围；前端只渲染给定差异，不自己比较字符串改判。

配置和原生业务共用上述内核。JSON 的 `uncertain_requires_review` 必须为 `true`。内核指纹变化后，旧草稿应重新验证与回放，不复制一套判定到配置服务。

## 从结论到工作台

`presentation/` 将比较和检查生成 `ReviewTask`，按实际页面顺序排列；声明字段缺失仍保留待复核提示。规则成功投影到字段后不再重复生成独立卡，投影失败时保留独立任务。任务的可见性与回填权限由后端声明，前端不维护第二份业务排除表。

每项展示页面原始值、材料候选、来源、状态、理由和原图。候选 `comparison_status` 独立于字段总状态，红色字段可以包含橙色不确定候选；不能把所有候选都染成已确认冲突。`check_reason` 随候选展示，`details.reason_distributed=true` 才可省略底部重复理由。规则 `page_values` 和 `page_value_note` 由后端提供，前端不从材料值拼出页面证据。

材料上传情况使用 `material_completeness.presence` 独立展示，不作为普通字段任务重复计数；内容完整性仍参与后端判定。主体关系隐藏交互与所有人一致性是两种不同结论，不应因名称相近一起过滤。

原图使用原始 URL，证据区域为整张图上的归一化坐标。材料值差异高亮和原图区域定位是不同坐标系，不互相套用。缺图片身份或定位区域时保留文字证据，不生成错误定位。

人工“已处理”只影响界面进度，不篡改机器状态或整体建议。颜色之外必须有文字/图标及禁用原因；网络、协议和业务错误分别反馈。新增任务优先复用统一工作台，特殊展示通过任务类型扩展，不在组件里加入地区政策。

## 受控页面动作

后端只返回 `action_id + payload` 等动作提议，不操作 DOM。浏览器只执行已注册动作；未知动作必须给可见提示。自动执行需要显式允许，需授权的动作等待人工确认。

```text
页面实例、步骤和记录身份 → 当前采集批次
  → 字段/控件类型白名单 → 唯一目标 → 原值校验
  → 控件交互写入 → 回读 → 成功定位或失败恢复
```

`writable` 综合业务动作、字段声明、控件可编辑性和允许控件类型；前端不能仅靠控件类型推断。正常字段有可靠候选时也可提供回填，“需不需要处理”与“允不允许写回”分开。

文本、下拉和日期使用相应适配器；组合字段作为同一动作校验和回读，不只修改一半。下拉精确核对真实选项和 ID，日期通过日历提交；失败恢复仍走同一交互。记录已变化时停止写入及恢复，避免写到另一条记录。

同一批次连续回填保留最初身份基准并更新已确认读值，重新采集建立新基准；未经受控写入的锚点变化仍判页面失效。成功回读后滚动定位并高亮，失败不能显示成功。金额等 DOM 回读格式兼容不改变后端审核结论。

共享地址有审核页签声明时，以唯一激活页签和对应可见面板确认步骤，核对 `aria-controls`、`aria-labelledby` 和面板关联。缺失、歧义或未就绪时不能用关键词或人工选择绕过。切走页签即作废旧采集，切回也需重采；未声明页签的普通页面继续使用路径和特征识别。
