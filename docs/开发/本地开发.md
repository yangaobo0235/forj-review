# 本地开发

## 环境与启动

Python 支持 3.11、3.12；Node.js 22.18+。本目录使用自己的 `.venv`、扩展依赖和 `.env`，不共享原项目的开发环境。

```powershell
uv sync --locked
# 首次创建，已有文件不要覆盖：
Copy-Item src/forj_review_service/.env.example src/forj_review_service/.env
uv run forj-review-service --reload
npm --prefix apps/review-extension ci
npm run dev:extension
```

IDEA 选择本目录 `.venv` 解释器，以模块 `forj_review_service.interfaces.cli` 启动，参数 `--host 127.0.0.1 --port 26101`。本版本不需要 IDEA 数据源或 SSH 隧道；隧道仅用于最初从原数据库只读导出数据。

## 环境变量

后端只读取 `src/forj_review_service/.env`；进程环境优先。密钥仅后端持有。`DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`、`DASHSCOPE_MODEL` 配置识别模型；`REVIEW_VEHICLE_API_BASE_URL`、`REVIEW_VEHICLE_API_TOKEN`、`REVIEW_VEHICLE_API_TIMEOUT` 配置车型业务服务。其余并发、图片源和日志选项见同目录 `.env.example`。

默认使用内置 JSON。可通过 `REVIEW_PAGES_DIR`、`REVIEW_ENGINE_EMISSIONS_FILE` 指定替代数据；`.env` 内相对路径以该文件目录解析，进程环境中的路径按启动目录解析。替代数据需完整有效，启动失败时不会使用测试夹具兜底。服务提供 `/health` 和只读 `/api/review/configuration/loaded` 运行快照诊断；没有配置编辑或发布接口。

## 规则文件维护

`data/pages/*.json` 为独立完整的 2.0 页面声明，每个页面须有唯一 `active=true` 版本。`data/engine-emissions.json` 为完整型号到国三/四/五/六的对应表。两类文件经原数据库只读导出，`data/source.json` 保存导出来源、原发布版本、摘要和有效规则指纹。不得用旧备份、离线候选或测试数据覆盖正式数据。

本版无配置后台，必要的规则调整由开发者修改文件、更新业务文档和来源记录，完成校验与回放后随版本发布。审核任务使用启动时的不可变快照；修改文件后重启。

```powershell
uv run forj-review-service --check-pages src/forj_review_service/data/pages
uv run forj-review-service --inspect-pages src/forj_review_service/data/pages
uv run forj-review-service --page-schema
# 固定材料回放，不调用模型或外部接口：
New-Item -ItemType Directory -Force .tmp/permit-pages
Copy-Item tests/fixtures/permit.json .tmp/permit-pages/permit.json
uv run forj-review-service --replay-pages .tmp/permit-pages --cases tests/fixtures/replay/permit-cases.json
```

回放目录必须只包含对应完整页面 JSON；示例可先将 `tests/fixtures/permit.json` 复制到临时单独目录，再传给 `--replay-pages`。普通审核不读取测试目录。

## 检查

后端运行 `uv run pytest -q`、Ruff、compileall 和 Python 架构检查。扩展运行 test、lint、format:check、build，并对采集或写回变更运行 `npm run test:extension:browser`。测试隔离开发者模型密钥、业务 API 和日志。详见[测试说明](../../tests/README.md)。
