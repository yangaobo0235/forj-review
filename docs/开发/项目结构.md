# 项目结构

## 目录与职责

| 目录 | 职责 |
| --- | --- |
| `apps/review-extension/src/app` | 审核侧栏页面、样式与入口组装 |
| 扩展 `features/review` | 请求、任务状态、证据展示及人工交互 |
| 扩展 `platform/browser` | 页面识别、字段/图片采集、控件写回与回读 |
| 扩展 `platform/extension` | 扩展消息、车型会话和浏览器 API |
| 扩展 `shared` | 纯契约、规范化与公共 UI |
| `src/forj_review_service/bootstrap` | HTTP 应用组装和资源生命周期 |
| 后端 `interfaces` | HTTP/CLI 输入输出与错误映射 |
| 后端 `runtime` | 审核图、能力编排、任务队列及离线规则验证 |
| 后端 `businesses` | 页面规则编译、政策、业务规则和材料路由 |
| 后端 `contracts`、`evidence` | 类型契约、事实及证据比较 |
| 后端 `integrations` | 模型、二维码、车型接口及 JSON 参考读取 |
| 后端 `presentation` | 后端审核结果到工作台任务的投影 |
| 后端 `config`、`observability` | 环境参数、日志及诊断 |
| 后端 `data` | 数据库导出的完整页面声明、排放参考及来源摘要 |
| `tests`、`scripts/ci` | 审核回归、架构检查和容器验证 |
| `deploy`、`scripts/release` | 单服务镜像、服务器脚本及发布包 |

没有审核配置管理前后端、共享数据库包、迁移工具或数据库服务。页面声明属于审核规则数据，保留编译和离线验证能力，不提供在线编辑或发布能力。

## 数据流

扩展先获取页面目录及采集清单，按真实页面采集字段与图片 URL，后端对每张图一次调用完成类型识别与内容提取，再按页面规则比较、执行能力并返回任务。扩展展示结论，由人工决定是否回填，最终审批在原业务系统完成。

服务启动完整加载 JSON，编译得到不可变业务 Profile；排放参考归一化为只读映射，多个审核线程共用。模型客户端和任务调度器仍由服务生命周期管理。任务和短期识别结果在内存保存，规则及参考数据随代码版本持久保存；无数据库连接、文件会话或跨进程任务恢复。

## 英文术语对照表

| 名称 | 含义 |
| --- | --- |
| Profile | 编译后的业务页面规则快照 |
| DOM | 浏览器页面文档对象模型 |
| Manifest | 页面采集或扩展权限清单 |
| API、API Key | 接口、接口密钥 |
| Token、Cookie | 访问令牌、会话凭据 |
| CLI、HTTP | 命令行入口、网络接口协议 |
| TTL | 内存数据的保留时限 |
| PR、Issue、CI | 合并请求、问题单、持续集成 |
| Conventional Commits | 约定式提交消息格式 |

接口类型由后端 `contracts` 与扩展 `shared/contracts` 同步维护；前端不重新计算后端业务结论，后端不操作页面 DOM。
