# 开发规范

## 1. 目标与范围

本版本仅保留审核业务及浏览器扩展，不提供审核配置管理服务，不使用 PostgreSQL、SQLite 或其他数据库。规则以完整 JSON 声明随代码维护，新算法、控件、外部接口及业务变化在对应代码模块实现。原项目 main 与本目录独立维护，禁止为本版修改原目录或数据库。

开始前检查工作区改动，保留用户未提交、暂存及未跟踪内容；阅读相关业务字段核对矩阵，不猜材料字段、证据顺序和政策。需求未知时调查或明确待确认项，不通过页面特例掩盖缺口。

## 2. 职责归属与协作边界

| 部分 | 负责内容 | 边界 |
| --- | --- | --- |
| 扩展页面适配 | DOM 身份、字段/图片采集、控件操作和回读 | 不计算政策、证据结论或调用数据库 |
| 扩展审核界面 | 任务、状态、证据展示，人工输入和选择 | 不重算后端结论，不改变机器判断 |
| 审核后端 | 识别、证据路由、字段比较、政策、任务和动作提议 | 不操作 DOM，不代替人工提交 |
| 集成层 | 模型/二维码/车型接口和 JSON 读取 | 不复制业务规则，不隐藏读取失败 |
| 规则数据 | 完整字段、材料、政策参数及已有能力组合 | 不保存可执行脚本或密钥 |
| 共享契约 | 请求、响应、动作与状态语义 | 不以类型声明代替边界验证 |

先确认事实来源与结论责任，沿采集、传递、处理、投影和显示定位根因；跨层变更同步生产方与消费者，各层只承担自己的职责。后端内 HTTP/CLI 负责输入输出，runtime 负责编排，businesses/evidence 负责判断，integrations 负责外部访问，presentation 负责任务投影。反复失败或需求调整时重新检查假设和设计，不持续堆补丁。

## 3. 代码与错误处理

Python 遵循 pyproject 的 Ruff 配置、100 字符行宽、Python 3.11 兼容范围；接口使用明确类型和现有 Pydantic 契约。Vue/TypeScript 使用统一 Prettier、类型检查和 ESLint。职责单一，控制流直接，注释解释真实业务约束；不使用复杂抽象、复制算法或压缩单行掩盖逻辑。

策略通过不可变上下文传递，不修改运行时全局政策；新能力通过登记接入。依赖、规则和参数保持单一来源。跨模块使用明确公开入口，不导入私有下划线函数；只为真实消费者维护导出。

区分业务不满足、证据不足、页面失效、网络故障与数据错误。只捕获可以处理的异常，边界返回稳定错误码与可操作提示。未知故障不反射原始异常值、密钥、请求正文或 URL 凭据；日志保留异常类型和调用位置。不能吞异常、伪造成功、用空数据兜底或任意放宽权限。重试和超时必须有真实依据、预算与可见结果。

## 4. 规则与数据

内置 `data/pages` 和 `data/engine-emissions.json` 来自原数据库只读导出，`data/source.json` 记录版本、来源及摘要。初始数据不采用本机备份、测试夹具或离线候选。需要再次导出时只读原本机 local 空间，不修改原数据、不触碰 public 和受保护目录表。

JSON 启动时完整校验并固定为内存快照，缺失、冲突、损坏直接启动失败，不部分采用。必要更新由开发者修改完整数据、同步业务矩阵及来源记录，编译/回放/测试后随镜像发布；修改后重启，回滚恢复配套镜像和规则。环境与密钥放 `.env` 或进程环境，不放业务 JSON。

## 5. 审核证据与写回

每个字段明确页面分区、材料字段、比较方式及回填权限。不猜字符、不投票、不用页面值挑 OCR 候选，不凭图片顺序猜材料。上传存在、识别质量与字段一致性分别处理，处理器成功不等于审核通过。字段独立核对，不加入未授权的 VIN 前置限制。

人工处理不改变机器结论，动作提议不等于已执行或业务验真成功。写前核对页面实例、激活步骤、记录、采集批次、唯一控件、权限及原值，写后回读；失败明确反馈，在身份仍有效时恢复。组合字段不能只写一半，车型按真实 ID 选择，规格由原业务系统带入。助手不自动提交审批。

## 6. 实现、清理与验证

同步移除被替代实现、无用导入、废弃入口、无消费者配置、依赖和说明，保留仍有效的兼容与保护。删除前核对静态引用、动态登记、CLI 和构建入口，不能凭名称或测试失败删除功能。私密配置、必要数据及用户内容须保留。

验证覆盖责任层及上下游，按变更选择业务正常、缺失、冲突和失败边界。规则变更验证编译、固定证据回放、审核接口和任务；前端采集/写回验证单元、lint/build 和浏览器场景；部署变更验证包校验、回滚及容器。测试不可访问真实模型或业务数据库，不把模拟通过说成现场审核通过。

完成标准：业务功能可达，职责清楚，废弃实现清理，受影响链路有验证依据。交付说明实际结果、风险及未验证范围，不把本地构建说成已部署。

## 7. 协作与文档

人和 AI 共用这些规范。不擅自提交、推送、部署或修改线上数据。正式说明优先更新已有文档；临时计划放被忽略的 `docs/开发计划/`。长期结论写回正式文档，不另建一套 AI 设计说明。新增业务使用[审核业务文档模板](../模板/审核业务文档模板.md)。
