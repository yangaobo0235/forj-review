# 数据库字段字典

本文集中说明目标结构v7的28张表。新增任务与URL采集目录、正式验证的约束与索引以迁移、ORM及隔离PostgreSQL系统目录核对；历史正式配置与受保护车型表保留既有结构。目标版本不代表所有环境已迁移，实际环境以显式迁移记录和就绪检查为准。

表的用途、关系、配置存储和清理规则见[数据库设计](数据库设计.md)。连接与显式迁移见[审核配置开发](../开发/审核配置开发.md)及[部署运维](../运维/部署运维.md)。

- `cfg_`、`ref_` 和 `sys_schema_migration` 由项目迁移管理，正常启动不建表。
- 四张官方检查点表按 LangGraph 协议管理。
- 四张 `forj_` 表保留导入结构及历史拼写；应用 ORM 只映射查询需要的部分列，不能据此裁剪源表。
- 默认值中的 `—` 表示数据库没有默认表达式，应用可能仍须显式传值。时间类型按实际结构列出，不改写源表时间文本。
- 下列约束和索引是结构参考，不是要求手工重复执行的建表脚本。触发器保护及应用契约同样生效，见[数据库设计](数据库设计.md)。

## 正式页面配置

### cfg_page

审核页面稳定身份

| 字段 | PostgreSQL 类型 | 必填 | 默认值/标识 | 含义 |
| --- | --- | --- | --- | --- |
| `id` | `bigint` | 是 | `GENERATED ALWAYS AS IDENTITY` | 稳定页面主键 |
| `page_code` | `text` | 是 | — | 稳定编码，例如 vehicle_source:default |
| `business_type` | `text` | 是 | — | 开发者已接入的业务编号 |
| `created_by` | `text` | 是 | — | 创建者；本机可为明确的 local 身份 |
| `created_at` | `timestamp with time zone` | 是 | `CURRENT_TIMESTAMP` | 创建时间 |

约束：

- `cfg_page_page_code_check`：`CHECK (btrim(page_code) <> ''::text)`。
- `cfg_page_page_code_key`：`UNIQUE (page_code)`。
- `cfg_page_pkey`：`PRIMARY KEY (id)`。

索引：

- `cfg_page_page_code_key`：`CREATE UNIQUE INDEX cfg_page_page_code_key ON local.cfg_page USING btree (page_code)`。
- `cfg_page_pkey`：`CREATE UNIQUE INDEX cfg_page_pkey ON local.cfg_page USING btree (id)`。

### cfg_page_version

| `title` | `text` | 是 | — | 当前版本标题 |
| `region_code` | `text` | 是 | — | 可扩展的地区标识，不使用固定城市枚举 |
| `enabled` | `boolean` | 是 | — | 当前版本是否启用 |

- `cfg_page_version_pkey`：`PRIMARY KEY (id)`。
- `cfg_page_version_schema_version_check`：`CHECK (schema_version = '2.0'::text)`。
- `cfg_page_version_version_no_check`：`CHECK (btrim(version_no) <> ''::text)`。

索引：

- `cfg_page_version_page_id_id_key`：`CREATE UNIQUE INDEX cfg_page_version_page_id_id_key ON local.cfg_page_version USING btree (page_id, id)`。
- `cfg_page_version_page_id_version_no_key`：`CREATE UNIQUE INDEX cfg_page_version_page_id_version_no_key ON local.cfg_page_version USING btree (page_id, version_no)`。

- `idx_page_version_history`：`CREATE INDEX idx_page_version_history ON local.cfg_page_version USING btree (page_id, id DESC)`。

## 迁移、历史与JSON职责

v4基线与005/006历史脚本不可改写。v5新增候选成组约束与版本化证明；v7保留legacy/1.0验证，并允许2.0目标属性检查上下文。`session_candidate_complete`以NOT VALID加入，保留旧报告缺少候选修订号的历史事实；新写入仍强制校验。`validation_task_identity`与任务/交互的组合外键限制验证归属。正式验证的`session_id`、发布的`source_session_id`保留原列名，不因聊天清理而丢失历史来源。

v7删除旧session表、图片字节表和旧采集，替换为上述八张工作流表。`context`只保存有界工作上下文与展示缓存；需求、执行轮次、交互、消息、工具结果和本地交付均有独立持久化归属。目标的依赖有效性、环和可编辑契约由应用验证，数据库保证对象类型、归属、唯一性和事务完整性。模型的处理决定不等于属性断言或业务回放通过。

事件与采集禁止UPDATE，正式历史保持原不可变触发器保护。任务删除可清理其过程子项，仍被其他任务引用的采集不得删除；正式发布与验证不随任务级联清理。具体清理周期、迁移范围和服务就绪边界见数据库设计。
