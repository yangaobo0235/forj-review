# 过户审核

2026-10-18：依据新版页面重新配置。业务身份为 `transfer | default | 1.0`，
`page_id=transfer:default`。青岛、长春共用配置。

## 页面与材料

在 `/consistency-qingdao`、`/consistency-changchun` 下，使用激活的“过户审核”页签和
关联可见面板识别步骤；不按共享路径猜审核步骤。字段分区为“审核过户凭证”和
“新车发票信息”。同名控件必须落在对应分区，分区缺失或目标重复时不猜测。

必传材料：登记证书1、2页、二手车发票、新车发票，三项都要上传。材料完整性按
上传事实展示，与 OCR 成败分开；页码覆盖另列内容检查。登记证3、4页暂不参加
识别和必传检查，不推断当前车主、过户记录或日期。

“过户资料”图片归入 `transfer_vehicle`；“新车发票”归入 `transfer_new`。
新车发票分组的唯一票据槽位明确声明为 `invoice`，避免分组名和图片名相同导致
未知类型。二手车发票使用独立的 `used_car_invoice` 类型，不能放入新车区代读。

共17个审核字段。开票日期、识别车架号均参与审核。全部字段优先按实际页面控件顺序展示；
已声明字段漏采时保留待复核项，按声明位置补入，禁止对缺失或歧义控件回填。
新车发票类型及两处发票代码不提取、不核对、不回填，也不生成审核任务。
订单、经销商、车源编号、车源名称、发布时间、主机厂等系统背景
不生成材料核对任务。“厂牌型号”只写品牌时原样核对，不补成完整销售车型。
金额使用十进制归一化，不能混用不含税价和税额；号码作为字符串保留前导零。
编号只消除格式和大小写差异，不擅自替换 O/0、I/1 等字符。

## 特殊规则与边界

- 旧车 VIN：每份材料独立与页面值比较。另一份缺失、识别不完整或两份冲突时，
  仍保留完整且非不确定的识别值供审核员选择回填，不要求两份材料先一致。
  不足17位的片段、不确定读值仍展示并提示核对原图，可通过人工输入补全后回填。
  整体结论仍检查两份材料完整性和一致性，不因回填操作自动判为通过，不用票数裁决。
- 新车 VIN：只核对新车发票。新旧车 VIN 不要求相同。
- 页面核对与票据验真分开。两处“一键验真”继续由业务系统各自按钮处理，助手不
  自动点击、不采信 OCR 一致性为验真成功，也不自动提交审核。
- 未配置买卖方与新车购方必须同主体、两张票日期先后、登记证初始车主必须等于
  本次卖方、不同登记阶段号牌必须相同等规则。后续只有业务口径明确后才能增加。

## 回填与实现

配置声明：`businesses/packs/transfer.py`。规则：`businesses/rules/transfer_documents.py`。
复用通用采集器、日期／下拉／文本写回器，不增加业务专属 DOM 适配器。
写入前校验页面、采集批次、原值及页签；写入后读回验证，再定位和高亮。
材料日期保留原文展示；回填时将有效的中文、斜杠、点号日期统一转为 `YYYY-MM-DD`，
通过共用日期控件处理器选择日历，再按日期语义读回验证。无效日期不写入。
表单项自身标签优先于全局 `label[for]`，避免两张发票复用控件 ID 导致串区或漏项。
分区查找穿过组件包装直到所属表单或页签边界，不以固定祖先层数截断；标题匹配忽略
排版空白。遇到不认识的明确分区标题仍停止继承，不跨区猜测同名字段。
已定位到的空控件保留空字符串、控件类型及回填目标，显示“未填写”并允许按业务规则回填；
未定位或存在歧义的控件显示“未采集”，禁止回填。材料间 VIN 冲突与各材料对页面值的
比较分别展示，不将整体冲突错误地套用到每个候选。
旧车 VIN、新车 VIN 构成独立记录锚点；修正其中一个时，另一个必须能证明仍是
原记录。没有独立记录标识时停止写回，要求重新读取或人工处理。

服务运行时不连接车型来源库、不调用业务系统数据接口，本次配置不改变离线车型查询。
生效需要重启审核服务、重新加载本地扩展并刷新业务页面后重新读取。
