# 过户审核

## 1. 业务范围与页面身份

| 项目 | 约定 |
| --- | --- |
| 业务与地区 | `transfer / default`，青岛长春共用 |
| 页面编码 | `transfer:default`，版本取内置 JSON 的活动页面声明 |
| 页面识别 | `/consistency-qingdao` 或 `/consistency-changchun`，激活“过户审核”及关联可见面板 |
| 页面分区 | 审核过户凭证、新车发票信息，同名字段必须分区定位 |
| 核对范围 | 二手车发票、旧车登记证及新购车辆发票 |
| 人工边界 | 票据验真和最终审批由业务系统人工处理 |

## 2. 材料清单与质量要求

| 材料及类型编码 | 分区 | 上传要求 | 识别/页码要求 |
| --- | --- | --- | --- |
| 登记证1、2页 `registration_certificate` | `transfer_vehicle` | 必传 | 原图真实页码 |
| 二手车发票 `used_car_invoice` | `transfer_vehicle` | 必传 | 独立票据类型，读取买卖方和市场相应栏位 |
| 新车销售发票 `invoice` | `transfer_new` | 必传 | 新车日期、号码、价税合计和 VIN |

三项都要上传，没有替代关系。新车组由页面确定业务分区，每张图片由内容确认实际资料类型并提取，不按张数或组内序号推断 `invoice`。材料齐全随内容分类逐张确认，标签不提前确认完整；已确认类型独立于后续字段 OCR 和页码覆盖；登记证3、4页不参与，不据此推断当前车主或过户日期。

## 3. 字段核对矩阵

2026-10-23 本机活动配置18条声明：17个页面审核字段、1个材料辅助输入。页面字段按实际控件顺序展示；漏采保留待复核，缺失/歧义目标禁止回填。

统一处理全半角及空白。号码始终为字符串，保留前导零，不替换 O/0、I/1；名称采用主体名称规范化。金额按十进制，日期按有效日期值比较。表中回填仍需第5节的权限与身份检查。

## 4. 组合核对与特殊规则

### R1 识别车架号独立核对

页面“识别车架号”仅与二手车发票的完整车辆识别代号比较，不要求与登记证或新车发票 VIN 一致。可靠差异为冲突，材料值和页面值保留字符差异供标红；缺失或不确定读值待复核。登记证仅用于当前声明的材料类型与页码完整性检查，不向本字段提供比较或回填候选。

### R2 新车 VIN 与分区隔离

新车 VIN 只对新车销售发票，不要求等于旧车 VIN。二手车票和新车票的日期、金额、号码分别映射，不能根据同名标签跨区取值。

### R3 验真及未配置规则

两处“一键验真”由业务系统人工按钮处理，助手不自动点击；OCR 一致不代表税务验真成功。不增加买卖方与新车购买方必须同主体、两票日期先后、登记证初始车主等于卖方或不同登记阶段号牌相同等未确认规则。

## 5. 回填与人工边界

17个页面字段使用共用文本/日期/下拉写回，不为本业务复制专用写回流程。已唯一定位的空控件显示未填写并可按权限回填；未采集或歧义控件禁止写入。表单项自身标签优先，深层分区查找不跨所属表单/页签边界，不以复用控件 ID 猜字段。

合法中文、斜杠或点号日期写回统一 `YYYY-MM-DD`，通过日期控件交互并按日期语义回读；无效日期不写。文本和金额写入后同样回读，失败明确提示并在身份有效时恢复。

旧、新 VIN 是独立记录锚点。修正其中一个时，另一锚点必须能证明仍属原记录；缺少独立身份依据就停止写回并重新读取。切换步骤/记录或批次后旧权限失效，不点击最终提交。
