# 车源审核

## 1. 业务范围与页面身份

| 项目 | 约定 |
| --- | --- |
| 业务与地区 | `vehicle_source / default`，青岛长春共用 |
| 页面编码 | `vehicle_source:default`，版本取活动发布 |
| 页面识别 | `/consistency-qingdao` 或 `/consistency-changchun`，激活“车源审核”及关联可见面板 |
| 页面分区 | 行驶证信息 `license`、规格参数 `spec` |
| 核对范围 | 行驶证信息、品牌型号补全、车型候选及规格回填 |
| 人工边界 | 具体销售版本由审核员选择，助手不提交/下一步 |

共享路径不能区分步骤。切换车辆、步骤、页面实例或采集批次使旧查询与回填失效；缺少唯一激活页签/面板不能通过手选业务绕过。

## 2. 材料清单与质量要求

| 材料及类型编码 | 分区 | 上传要求 | 识别/页码要求 |
| --- | --- | --- | --- |
| 行驶证正面 `vehicle_license` | `vehicle` | 必传 | 正面真实字段；号码与型号分开 |
| 登记证1、2页 `registration_certificate` | `vehicle` | 与铭牌至少一种 | 可见页码、整车型号、发动机型号和 VIN |
| 铭牌 `vehicle_nameplate` | `vehicle` | 与登记证至少一种 | 铭牌真实型号和 VIN，不推导销售版本 |

行驶证反面、登记证3/4页及车况/附件区不参与本次识别。上传事实、页码质量、OCR 读值和字段比较分别反馈；不按图片顺序或数量猜类型，未确认标签保留待确认。

## 3. 字段核对矩阵

2026-10-20 本机活动声明共21条：19个页面字段及2个材料专用输入，其中9个为审核字段。声明数、采集数和审核项数须区分。通用规范化处理空白和全半角；号码保留前导零，不猜字符，日期按日期值比较。

### 3.1 页面审核字段

| 页面字段及稳定键 | 材料与材料字段 | 比较及关联规则 | 回填 |
| --- | --- | --- | --- |
| 车牌号码 `vehicle.plate_no` | 行驶证正面号牌号码 `vehicle.plate_no` | 完整号码，忽略空白和大小写 | 单字段 |
| VIN `vehicle.vin` | 行驶证完整 VIN `vehicle.vin`；辅助登记证/铭牌同键 | 行驶证为核对依据，辅助只校验同车；不比后8位，见 R1 | 可靠行驶证完整值 |
| 发动机号 `vehicle.engine_no` | 行驶证发动机号码 `vehicle.engine_no` | 完整号码；不能用发动机型号替代 | 单字段 |
| 行驶证车辆类型 `vehicle.license_type` | 行驶证完整车辆类型 `vehicle.license_type` | 完整文字比较，不折叠轻重型或车辆大类 | 单字段 |
| 注册日期 `vehicle.registration_date` | 行驶证注册日期 `vehicle.registration_date` | 按日期值比较，不与发证日期混用 | 单字段日期 |
| 发证日期 `vehicle.issue_date` | 行驶证发证日期 `vehicle.issue_date` | 按日期值比较，不使用检验期 | 单字段日期 |
| 所有人 `vehicle.owner` | 行驶证所有人 `vehicle.owner` | 主体名称规范化比较 | 单字段 |
| 品牌型号 `vehicle.brand_model` | 行驶证 `vehicle.brand_model`＋辅助整车型号 | 专用补全规则，仅前缀兼容，详见 R2 | 可靠完整组合值 |
| 车型 `vehicle.model` | 材料两个型号＋页面范围→目录候选 | 始终人工选择具体车型 ID，不直接 OCR 比较销售版本，见 R3 | 选择后整块规格回填 |

### 3.2 查询范围、规格与材料输入

| 页面字段及稳定键 | 材料与材料字段 | 比较及关联规则 | 回填 |
| --- | --- | --- | --- |
| 车辆类型 `vehicle.type` | 页面规格参数中的车辆类型 | 仅限定车型查询范围；不是行驶证完整车辆类型字段 | 禁止 |
| 品牌 `spec.brand` | 页面原值；所选目录品牌及真实 ID | 查询范围和整块回填，不独立 OCR 核对 | 随车型整块 |
| 车系 `spec.series` | 页面原值；所选目录车系及业务 series_id | 查询范围和整块回填，不能用内部车系主键替代 | 随车型整块 |
| 驱动形式 `spec.drive_form` | 所选车型目录驱动形式 | 规格参数，不从材料推断 | 随车型整块 |
| 燃料种类 `spec.fuel_type` | 所选车型目录燃料种类 | 规格参数，不独立产生材料核对项 | 随车型整块 |
| 排放标准 `spec.emission_standard` | 所选车型目录排放标准 | 规格参数，不按车源图片推导 | 随车型整块 |
| 最大马力 `spec.max_hp` | 所选车型目录最大马力 | 规格参数，不用型号反推马力 | 随车型整块 |
| 发动机品牌 `spec.engine_brand` | 所选车型目录发动机品牌 | 规格参数，区别于整车品牌 | 随车型整块 |
| 发动机型号 `spec.engine_model` | 所选车型目录发动机型号 | 规格参数，区别于材料搜索条件字段 | 随车型整块 |
| 货箱长度 `spec.cargo_length` | 所选车型目录货箱长度 | 可用值回填；目录缺失保留/恢复原值，见 R4 | 随车型整块或恢复原值 |
| 整车型号 `vehicle.announcement_model` | 登记证/铭牌整车型号 `vehicle.announcement_model` | 材料辅助输入，供补全和精确查询，不是页面控件 | 禁止直接写为车型名 |
| 发动机型号（材料） `vehicle.engine_model` | 登记证/铭牌发动机型号 `vehicle.engine_model` | 材料辅助输入，保留完整后缀，不能用号码替代 | 禁止直接写为车型名 |

使用性质和地址不在核对范围。`vehicle.type` 是页面查询范围，`vehicle.license_type` 才是行驶证完整类型；`spec.engine_model` 是页面参数，`vehicle.engine_model` 是材料输入，不能互换。

## 4. 组合核对与特殊规则

### R1 行驶证为依据及同车检查

牌号、完整 VIN、发动机号码、完整类型、注册/发证日期、所有人均取行驶证。登记证/铭牌 VIN 只检查辅助资料是否同车，不替代行驶证权威值。辅助 VIN 与行驶证冲突时不生成可信补全/自动搜索条件，交人工核对；行驶证缺失也不能凭辅助材料宣布一致。

### R2 品牌型号补全

行驶证品牌文字保留，与登记证/铭牌的整车型号仅做前缀兼容补全：例如 `解放牌CA4255P25K2T1E6A` 与 `CA4255P25K2T1E6A80` 可得到带品牌的完整值。完整型号相同也可；互相矛盾、不确定或 VIN 冲突不补全。

只有根本未提供辅助整车型号输入时才可回退行驶证型号；辅助已有字段但空值、冲突或不确定不能通过回退掩盖。发动机不确定影响车型搜索，不影响独立可靠的品牌型号补全。原始截断值、不带品牌型号作为证据，不能冒充完整回填值。

### R3 车型精确查询

五个条件为 **整车型号、发动机型号、页面品牌、页面车系、页面车辆类型**。材料两个型号可以人工修改，页面三个范围仍保留。两个型号保留完整后缀，只做既有规范化，不用发动机号码、马力反推或模糊相似值替代。

页面品牌/车系名称在目录内唯一解析为真实编号，再限定类型并同时精确匹配两个型号；只查未删除、已启用记录。缺范围要求重新读取，歧义/必要配置缺失明确报错，不扩大到全库。零条、一条、多条都是正常结果，即使一条也不自动选择。同名不同 ID 分别保留，名称相同不证明销售版本相同。

查询自身目标 Schema 的四张源目录表：`forj_vehicle_brand`、`forj_vehicle_series`、`forj_vehicle_model`、`forj_vehicle_model_config`，加自有派生索引 `ref_vehicle_model_key`。配置按 `model_id` 关联；车型 `s_id` 对车系内部 `id`，查询/回填的 `series_id` 是业务编号，不能混用。运行不访问来源库和业务接口。

四张源目录为受保护数据，普通配置维护不修改。刷新需独立授权、同一来源一致性快照、完整备份和暂存校验，整体切换，显式重建派生表并记录导入台账；不能逐表覆盖造成混合批次，也不导入申请/正式车源快照、用户、菜单等无关表。数据关系见[数据库设计](../数据/数据库设计.md)。配置回滚不恢复目录数据。

### R4 规格回填与缺项

人工选择具体 ID 后预览，按品牌→车系→车型→规格顺序回填。品牌、车系、车型必须核验实时选项真实 ID，不能点同名首项或按可见顺序猜。缺少必需参数阻止整块；货箱长度没有目录值时保留原值，被父级联动清空则恢复原值。

回填前重新查询目录并比较可信配置；发生变化要求重新搜索。完成后逐项回读，父级联动重建控件时重新定位。部分失败明确反馈真实完成情况；车型仍需人工确认，重新审核不会因为页面名称相同自动通过。

## 5. 回填与人工边界

普通行驶证字段走统一回填；车型仅走候选选择和整块规格操作，两个搜索型号不能直接回填成车型名称。没有可信候选的值可以核对原图后人工处理，不能用不确定 OCR 自动写入。

查询中、无匹配、范围歧义、配置缺项和通信错误分别显示；手动修改条件清空旧候选/选择，不被迟到识别覆盖。字段切换保留同条件查询，页面身份或范围变化立即作废。选择跨分页保留具体 ID，并提供完整预览。

可信候选由扩展后台按标签页/页面实例/记录指纹/采集批次保存，不能接受侧栏任意自带配置作为写回依据。回填前实时重读三个范围值及实际路由；发生改变就停止。页面失效不恢复到其他记录，不点击业务提交。

## 7. 维护约定

字段增删或来源变化同步更新本页矩阵、规则依赖与对应验证。已有能力内改配置，新算法、控件和外部接口由开发扩展。发布后重新采集，核对服务实际加载；历史版本保留用于回滚。

本文说明业务口径，不复制整份活动配置、不记录开发流水。通用机制见[审核执行原理](../开发/审核执行原理.md)，开发要求见[开发规范](../开发/开发规范.md)，操作见[审核配置使用](../使用/审核配置使用.md)。
