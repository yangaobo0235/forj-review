# 车源审核

## 1. 业务范围与页面身份

| 项目 | 约定 |
| --- | --- |
| 业务与地区 | `vehicle_source / default`，青岛长春共用 |
| 页面编码 | `vehicle_source:default`，版本取活动发布 |
| 页面识别 | `/consistency-qingdao` 或 `/consistency-changchun`，激活“车源审核”及关联可见面板 |
| 页面分区 | 行驶证信息 `license`、规格参数 `spec` |
| 核对范围 | 行驶证信息、品牌型号补全、车型候选及规格回填 |
| 人工边界 | 具体销售版本由审核员选择，助手不提交/下一步 |

共享路径不能区分步骤。切换车辆、步骤、页面实例或采集批次使旧查询与回填失效；缺少唯一激活页签/面板不能通过手选业务绕过。

## 2. 材料清单与质量要求

| 材料及类型编码 | 分区 | 上传要求 | 识别/页码要求 |
| --- | --- | --- | --- |
| 行驶证正面 `vehicle_license` | `vehicle` | 必传 | 正面真实字段；号码与型号分开 |
| 登记证1、2页 `registration_certificate` | `vehicle` | 与铭牌至少一种 | 可见页码、整车型号、发动机型号和 VIN |
| 铭牌 `vehicle_nameplate` | `vehicle` | 与登记证至少一种 | 铭牌真实型号和 VIN，不推导销售版本 |

行驶证反面、登记证3/4页及车况/附件区不参与本次识别。上传事实、页码质量、OCR 读值和字段比较分别反馈；不按图片顺序或数量猜类型，未确认标签保留待确认。

## 3. 字段核对矩阵

2026-10-20 本机活动声明共21条：19个页面字段及2个材料专用输入，其中9个为审核字段。声明数、采集数和审核项数须区分。通用规范化处理空白和全半角；号码保留前导零，不猜字符，日期按日期值比较。

### 3.1 页面审核字段

| 页面字段及稳定键 | 材料与材料字段 | 比较及关联规则 | 回填 |
| --- | --- | --- | --- |
| 车牌号码 `vehicle.plate_no` | 行驶证正面号牌号码 `vehicle.plate_no` | 完整号码，忽略空白和大小写 | 单字段 |
| VIN `vehicle.vin` | 行驶证完整 VIN `vehicle.vin`；辅助登记证/铭牌同键 | 行驶证为核对依据，辅助只校验同车；不比后8位，见 R1 | 可靠行驶证完整值 |
| 发动机号 `vehicle.engine_no` | 行驶证发动机号码 `vehicle.engine_no` | 完整号码；不能用发动机型号替代 | 单字段 |
| 行驶证车辆类型 `vehicle.license_type` | 行驶证完整车辆类型 `vehicle.license_type` | 完整文字比较，不折叠轻重型或车辆大类 | 单字段 |
| 注册日期 `vehicle.registration_date` | 行驶证注册日期 `vehicle.registration_date` | 按日期值比较，不与发证日期混用 | 单字段日期 |
| 发证日期 `vehicle.issue_date` | 行驶证发证日期 `vehicle.issue_date` | 按日期值比较，不使用检验期 | 单字段日期 |
| 所有人 `vehicle.owner` | 行驶证所有人 `vehicle.owner` | 主体名称规范化比较 | 单字段 |
| 品牌型号 `vehicle.brand_model` | 行驶证 `vehicle.brand_model`＋辅助整车型号 | 专用补全规则，仅前缀兼容，详见 R2 | 可靠完整组合值 |
| 车型 `vehicle.model` | 页面品牌 ID、业务车系 ID、基础信息车辆类型＋材料型号→业务接口候选 | 始终人工选择具体车型 ID，不直接 OCR 比较销售版本，见 R3 | 选择后整块规格回填 |

### 3.2 查询范围、规格与材料输入

| 页面字段及稳定键 | 材料与材料字段 | 比较及关联规则 | 回填 |
| --- | --- | --- | --- |
| 车辆类型 `vehicle.type` | 页面车源基础信息中的车辆类型 | 固定必传查询条件 `typeLevel`，仅取基础信息当前选值，不借用行驶证完整类型 | 禁止 |
| 品牌 `spec.brand` | 页面所选品牌及真实 ID | 必传的固定查询范围，不独立 OCR 核对 | 仅核验并保留原选择 |
| 车系 `spec.series` | 页面所选车系及业务 series_id | 必传的固定查询范围，采用页面真实业务 ID，不提供侧栏车系下拉 | 仅核验并保留原选择 |
| 驱动形式 `spec.drive_form` | 所选车型目录驱动形式 | 规格参数，不从材料推断 | 随车型整块 |
| 燃料种类 `spec.fuel_type` | 所选车型目录燃料种类 | 规格参数，不独立产生材料核对项 | 随车型整块 |
| 排放标准 `spec.emission_standard` | 所选车型目录排放标准 | 规格参数，不按车源图片推导 | 随车型整块 |
| 最大马力 `spec.max_hp` | 所选车型目录最大马力 | 规格参数，不用型号反推马力 | 随车型整块 |
| 发动机品牌 `spec.engine_brand` | 所选车型目录发动机品牌 | 规格参数，区别于整车品牌 | 随车型整块 |
| 发动机型号 `spec.engine_model` | 所选车型目录发动机型号 | 规格参数，区别于材料搜索条件字段 | 随车型整块 |
| 货箱长度 `spec.cargo_length` | 页面原值 | 新接口不提供此字段；旧发布配置仍声明保留时按原映射恢复，见 R4 | 仅历史配置保留原值 |
| 整车型号 `vehicle.announcement_model` | 登记证/铭牌整车型号 `vehicle.announcement_model`＋行驶证图片品牌型号 | 默认搜索条件，沿用 R2 的材料解析与前缀补全规则，仅取不带品牌汉字的型号；禁止取页面品牌型号 | 禁止直接写为车型名 |
| 发动机型号（材料） `vehicle.engine_model` | 登记证/铭牌图片发动机型号 `vehicle.engine_model` | 默认搜索条件，保留完整后缀，不能用号码或页面规格字段替代 | 禁止直接写为车型名 |

使用性质和地址不在核对范围。`vehicle.type` 是固定车型查询条件，`vehicle.license_type` 才是行驶证完整类型；`spec.engine_model` 是页面参数，`vehicle.engine_model` 是材料输入，不能互换。

## 4. 组合核对与特殊规则

### R1 行驶证为依据及同车检查

牌号、完整 VIN、发动机号码、完整类型、注册/发证日期、所有人均取行驶证。登记证/铭牌 VIN 只检查辅助资料是否同车，不替代行驶证权威值。辅助 VIN 与行驶证冲突时不生成可信补全/材料搜索条件，交人工核对；行驶证缺失也不能凭辅助材料宣布一致。

### R2 品牌型号补全

行驶证品牌文字保留，与登记证/铭牌的整车型号仅做前缀兼容补全：例如 `解放牌CA4255P25K2T1E6A` 与 `CA4255P25K2T1E6A80` 可得到带品牌的完整值。完整型号相同也可。例如行驶证 `欧曼牌BJ4259SNFKB-X` 与辅助型号 `BJ4259SNFKB-XJ`，完整值为 `欧曼牌BJ4259SNFKB-XJ`；中间字符不同、不确定或辅助型号冲突不能补全。

只有根本未提供辅助整车型号输入时才可回退行驶证型号；辅助已有字段但空值、冲突或不确定不能通过回退掩盖。发动机不确定影响车型搜索，不影响独立可靠的品牌型号补全。原始截断值、不带品牌型号作为证据，不能冒充完整回填值。

品牌型号卡片先展示页面当前值及后端合成结论，完整型号独占整行，补全后缀突出显示；只用完整品牌型号核对页面，例如行驶证 `陕汽牌SX4259MD4TL` 与登记证书 `SX4259MD4TLQ1` 合成 `陕汽牌SX4259MD4TLQ1`，页面完整一致才通过。可信完整值可一键回填，已一致时无需重复回填。材料依据与原图合并为默认展开的区域，每条材料读值旁保留对应缩略图及查看原图入口；人工填写独立直接展示。VIN 冲突时，若型号本身可靠且前缀兼容，可展示“待核实组合值”，但不生成可信推荐值或自动回填权限；缺失、冲突及不确定原因明确展示，冲突理由只展示一次。回填与机器核验分离，自动或人工回填后仍需重新审核，不由前端直接改变机器结论。

### R3 车型精确查询

侧栏按 **固定页面品牌、车辆类型和车系 → 材料型号 → 全部候选 → 人工选择 → 六项规格预览及回填** 操作。三个固定条件来自业务页当前选值，必须核验真实 ID；`typeLevel` 只取车源基础信息，不取行驶证完整类型。车系使用业务 `series_id`，不能用内部 `s_id`/车系行 ID 替代。侧栏没有车系下拉或清空范围功能，也不再查询品牌/车系列表。

原生 select 读取选中 option；Ant 控件读取对应 ASelect 的选中值、fieldNames 及显示标签，车系值字段必须是业务 `seriesId`。远程选项未加载时当前 ID 与标签仍可用于范围校验；已加载的同 ID 标签与显示不一致则报错。单项读取失败按字段提示；品牌、车系或基础类型缺失阻止查询，车型未加载不阻止查询。没有完整原页面选择快照不能回填。查询前后重读三个固定条件，任一变化或记录身份变化均丢弃结果。

两个型号分别可选，均填时 AND 精确匹配，只填一个仅限制该型号，均空时浏览固定页面范围，接口及侧栏均不分页。默认值仅来自后端判定可靠的图片证据：整车型号沿用 R2 的解析和前缀补全，去掉品牌汉字；仅根本未提供辅助型号时使用行驶证图片型号。发动机取登记证/铭牌，不从页面参数回退。保留完整后缀，不用号码、马力或模糊型号替代。VIN 冲突时两个默认条件清空，其他型号冲突或不确定只清空对应条件，并保留原因和原图。

范围有效且至少取得一个可靠型号时自动查询。人工修改后不被迟到识别覆盖；恢复材料型号时采用最新材料值。手动搜索可以清空两个型号浏览当前范围。零条、一条、多条都是正常结果，一条也不自动选择；同名不同 ID 分别展示，由审核员核对六项规格后选择。

扩展调用审核服务 `POST /api/review/vehicle-models/search`：

```json
{"pageScope":{"brandId":"6","brandName":"东风商用车","seriesId":"7235","seriesName":"示例车系","typeLevel":"牵引车"},"announcementModel":"DFH4250A4","engineModel":"DCI450-51"}
```

审核后端转发到 `REVIEW_VEHICLE_API_BASE_URL` 下的 `POST /vehicle-model/review/search`，将 `pageScope.seriesId` 映射为 `serialId`，只发送 `brandId`、`serialId`、`typeLevel` 和两个型号。上游成功包为 `code=0,data=[...]`；审核服务返回 `{candidates:[...]}`，无分页或单独详情调用。候选仅有 `modelId`、`modelName`、`config`，其中 config 必须包含六个可空字符串：`driveForm`、`fuelType`、`emissionStandard`、`maxHp`、`engineBrand`、`engineType`。缺少任一键、重复/无效车型 ID、非零业务码或请求失败均作为错误，不当作无候选。可空规格交由回填完整性检查阻止缺项写入。

业务接口由 `forj-vehicle` 实现，预期由业务方查询 `forj_vehicle_model` 并按 `model_id` 关联 `forj_vehicle_model_config`，使用启用、未删除及固定范围、完整型号条件。本项目只消费上述契约，不访问本地四张 `forj_` 副本、`ref_vehicle_model_key` 或 `ref_engine_emission`，不作本地数据兜底。接口地址及运行配置见[本地开发](../开发/本地开发.md)。

### R4 规格回填与缺项

人工选择具体 ID 后预览，先核验固定品牌、车系、车辆类型和完整选择快照，再按车型→六项规格顺序写入，品牌和车系不写入。车型必须按实时真实 ID 唯一选择，不能点同名首项。目标选项暂缺可以有限等待，重复、禁用和页面变化立即停止。同 ID 名称有别名时使用实时选项标签核验。预览按真实 ID 统计变更，同名不同 ID 仍计为变更。六项规格缺少任一值阻止整块回填。

新生成的动作映射仅含车型和六项规格。已有发布的 v1 映射及摘要保持原样：品牌/车系映射解释为原页面选择前置条件，只完成依赖校验、不执行写入；旧配置显式声明货箱长度 `RESTORE_ORIGINAL` 时，接口无该值，按原映射保留/恢复页面值。此兼容不添加字段权限，也不更改配置内容。后续配置调整仍走预览、验证和确认发布。

回填前重新调用候选业务接口并比较可信配置；发生变化要求重新搜索。切换 Ant 车型控件时，在点击前开始观察业务页面自身的 `/vehicle-model/config/detail` 请求，确认本次请求完成并让页面更新后再填写规格，避免异步加载覆盖已填值；扩展不发送此请求，不读取响应正文。请求失败、15 秒内未确认完成或无法观察时停止后续写入，要求核对页面并重新采集。完成后逐项回读，父级联动重建控件时重新定位。

部分失败明确反馈真实完成情况。车型已成功写入并核验真实 ID 时，即使后续规格失败，也在核验品牌、车辆类型及其余选择未发生意外变化后更新本地选择基准，允许在当前采集内重试；失败项仍标为未确认，不能视为整块成功。无法确认选项身份或发生额外变化时仍需重新采集。车型仍需人工确认，重新审核不会因为页面名称相同自动通过。

## 5. 回填与人工边界

普通行驶证字段走统一回填；车型仅走候选选择和整块规格操作，两个搜索型号不能直接回填成车型名称。没有可信候选的值可以核对原图后人工处理，不能用不确定 OCR 自动写入。

查询中、无匹配、范围歧义、配置缺项和通信错误分别显示；手动修改条件清空旧候选/选择，不被迟到识别覆盖。字段切换保留同条件查询，页面身份或范围变化立即作废。全部候选保留具体 ID，并提供完整预览。

可信候选由扩展后台按标签页/页面实例/记录指纹/采集批次保存，不能接受侧栏任意自带配置作为写回依据。后台在目录查询前后向原业务主页面重读范围，核对本次采集身份和 `pageModelScope`，侧栏范围不一致则拒绝；材料筛选不能改变固定品牌、车系与车辆类型。原页面 `pageSelection` 保留品牌、车系、车型 ID/名称及类型快照，回填前再次核验；同名不同 ID 也判定页面变化。已确认的本次写入更新本地读值基准，新的采集建立新基准。页面失效不恢复到其他记录，不点击业务提交。

## 7. 维护约定

字段增删或来源变化同步更新本页矩阵、规则依赖与对应验证。已有能力内改配置，新算法、控件和外部接口由开发扩展。发布后重新采集，核对服务实际加载；历史版本保留用于回滚。

本文说明业务口径，不复制整份活动配置、不记录开发流水。通用机制见[审核执行原理](../开发/审核执行原理.md)，开发要求见[开发规范](../开发/开发规范.md)，操作见[审核配置使用](../使用/审核配置使用.md)。
