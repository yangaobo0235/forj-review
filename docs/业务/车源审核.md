# 车源审核

## 1. 业务范围与页面身份

| 项目 | 约定 |
| --- | --- |
| 业务与地区 | `vehicle_source / default`，青岛长春共用 |
| 页面编码 | `vehicle_source:default`，版本取活动发布 |
| 页面识别 | `/consistency-qingdao` 或 `/consistency-changchun`，激活“车源审核”及关联可见面板 |
| 页面分区 | 行驶证信息 `license`、规格参数 `spec` |
| 核对范围 | 行驶证信息、品牌型号补全、车型候选及车型回填 |
| 人工边界 | 具体销售版本由审核员选择，助手不提交/下一步 |

共享路径不能区分步骤。切换车辆、步骤、页面实例或采集批次使旧查询与回填失效；缺少唯一激活页签/面板不能通过手选业务绕过。

## 2. 材料清单与质量要求

| 材料及类型编码 | 分区 | 上传要求 | 识别/页码要求 |
| --- | --- | --- | --- |
| 行驶证正面 `vehicle_license` | `vehicle` | 必传 | 正面真实字段；号码与型号分开 |
| 登记证1、2页 `registration_certificate` | `vehicle` | 与铭牌至少一种 | 可见页码、整车型号、发动机型号和 VIN |
| 铭牌 `vehicle_nameplate` | `vehicle` | 与登记证至少一种 | 铭牌真实型号和 VIN，不推导销售版本 |

行驶证反面、登记证3/4页及车况/附件区不参与本次识别。上传事实、页码质量、OCR 读值和字段比较分别反馈；不按图片顺序或数量猜类型，上传标签仅作线索；类型由内容逐张确认，识别前不提前显示齐全。

## 3. 字段核对矩阵

2026-10-20 本机活动声明共21条：19个页面字段及2个材料专用输入，其中9个为审核字段。声明数、采集数和审核项数须区分。通用规范化处理空白和全半角；号码保留前导零，不猜字符，日期按日期值比较。

### 3.1 页面审核字段

| 页面字段及稳定键 | 材料与材料字段 | 比较及关联规则 | 回填 |
| --- | --- | --- | --- |
| 车牌号码 `vehicle.plate_no` | 行驶证正面号牌号码 `vehicle.plate_no` | 完整号码，忽略空白和大小写 | 单字段 |
| VIN `vehicle.vin` | 行驶证完整 VIN `vehicle.vin` | 只按该字段已配置来源核对完整号码，不比后8位，不作为其他字段前置条件，见 R1 | 可靠行驶证完整值 |
| 发动机号 `vehicle.engine_no` | 行驶证发动机号码 `vehicle.engine_no` | 完整号码；不能用发动机型号替代 | 单字段 |
| 行驶证车辆类型 `vehicle.license_type` | 行驶证完整车辆类型 `vehicle.license_type` | 完整文字比较，不折叠轻重型或车辆大类 | 单字段 |
| 注册日期 `vehicle.registration_date` | 行驶证注册日期 `vehicle.registration_date` | 按日期值比较，不与发证日期混用 | 单字段日期 |
| 发证日期 `vehicle.issue_date` | 行驶证发证日期 `vehicle.issue_date` | 按日期值比较，不使用检验期 | 单字段日期 |
| 所有人 `vehicle.owner` | 行驶证所有人 `vehicle.owner` | 主体名称规范化比较 | 单字段 |
| 品牌型号 `vehicle.brand_model` | 行驶证 `vehicle.brand_model`＋辅助整车型号 | 保留行驶证品牌文字并组合材料整车型号；差异给出结论，不阻止人工选择回填，不依赖 VIN，详见 R2 | 人工判断后回填组合值或手动填写 |
| 车型 `vehicle.model` | 页面品牌 ID、业务车系 ID、基础信息车辆类型＋材料型号→业务接口候选 | 始终人工选择具体车型 ID，不直接 OCR 比较销售版本，见 R3 | 仅选择车型，其余由业务系统联动带入 |

### 3.2 查询范围、规格与材料输入

| 页面字段及稳定键 | 材料与材料字段 | 比较及关联规则 | 回填 |
| --- | --- | --- | --- |
| 车辆类型 `vehicle.type` | 页面车源基础信息中的车辆类型 | 固定必传查询条件 `typeLevel`，仅取基础信息当前选值，不借用行驶证完整类型 | 禁止 |
| 品牌 `spec.brand` | 页面所选品牌及真实 ID | 必传的固定查询范围，不独立 OCR 核对 | 仅核验并保留原选择 |
| 车系 `spec.series` | 页面所选车系及业务 series_id | 必传的固定查询范围，采用页面真实业务 ID，不提供侧栏车系下拉 | 仅核验并保留原选择 |
| 驱动形式 `spec.drive_form` | 原业务系统按所选车型带出的驱动形式 | 规格参数，不从材料推断 | 助手不写入，由原业务系统带入 |
| 燃料种类 `spec.fuel_type` | 原业务系统按所选车型带出的燃料种类 | 规格参数，不独立产生材料核对项 | 助手不写入，由原业务系统带入 |
| 排放标准 `spec.emission_standard` | 原业务系统按所选车型带出的排放标准 | 规格参数，不按车源图片推导 | 助手不写入，由原业务系统带入 |
| 最大马力 `spec.max_hp` | 原业务系统按所选车型带出的最大马力 | 规格参数，不用型号反推马力 | 助手不写入，由原业务系统带入 |
| 发动机品牌 `spec.engine_brand` | 原业务系统按所选车型带出的发动机品牌 | 规格参数，区别于整车品牌 | 助手不写入，由原业务系统带入 |
| 发动机型号 `spec.engine_model` | 原业务系统按所选车型带出的发动机型号 | 规格参数，区别于材料搜索条件字段 | 助手不写入，由原业务系统带入 |
| 货箱长度 `spec.cargo_length` | 页面原值 | 助手不获取、不恢复该值，原业务系统决定联动行为，见 R4 | 助手不写入 |
| 整车型号 `vehicle.announcement_model` | 登记证/铭牌整车型号 `vehicle.announcement_model`＋行驶证图片品牌型号 | 默认搜索条件，沿用 R2 的材料解析，仅取不带品牌汉字的型号；禁止取页面品牌型号 | 禁止直接写为车型名 |
| 发动机型号（材料） `vehicle.engine_model` | 登记证/铭牌图片发动机型号 `vehicle.engine_model` | 默认搜索条件，保留完整后缀，不能用号码或页面规格字段替代 | 禁止直接写为车型名 |

使用性质和地址不在核对范围。`vehicle.type` 是固定车型查询条件，`vehicle.license_type` 才是行驶证完整类型；`spec.engine_model` 是页面参数，`vehicle.engine_model` 是材料输入，不能互换。

## 4. 组合核对与特殊规则

### R1 行驶证字段独立核对

牌号、完整 VIN、发动机号码、完整类型、注册/发证日期、所有人均取行驶证，按各字段配置核对。品牌型号和车型搜索不消费 VIN，不以其他字段的结果阻断本字段。行驶证缺失不能凭辅助材料宣布行驶证字段一致。

### R2 品牌型号补全

保留行驶证品牌文字，组合登记证/铭牌的整车型号。例如 `欧曼牌BJ4259SNFKB-X` 与辅助型号 `BJ4259SNFKB-XJ`，组合值为 `欧曼牌BJ4259SNFKB-XJ`。型号不满足前缀兼容时仍给出组合值和材料差异结论，由人工决定是否回填；例如 `解放牌CA4250P66K25T1A1E` 与登记证 `LZ4250H6NB5T1A1ES`，展示 `解放牌LZ4250H6NB5T1A1ES`，同时标记材料型号不一致，不宣称审核通过，不禁用该组合值的人工回填。

只有根本未提供辅助整车型号输入时才可回退行驶证型号；辅助已有字段但空值、冲突或不确定不能通过回退掩盖。发动机不确定影响车型搜索，不影响独立可靠的品牌型号补全。原始截断值、不带品牌型号作为证据，不能冒充完整回填值。

品牌型号卡片先展示页面当前值及后端合成结论，完整型号独占整行，补全后缀突出显示；只用完整品牌型号核对页面，例如行驶证 `陕汽牌SX4259MD4TL` 与登记证书 `SX4259MD4TLQ1` 合成 `陕汽牌SX4259MD4TLQ1`，页面完整一致才通过。可信完整值可一键回填，已一致时无需重复回填。材料依据与原图合并为默认展开的区域，每条材料读值旁保留对应缩略图及查看原图入口；人工填写独立直接展示。品牌型号只消费材料中的品牌与型号，不把 VIN 缺失、冲突或不确定作为补全、字段核对或回填的前置条件，也不展示 VIN 原因。型号本身缺失、冲突及不确定原因明确展示，冲突理由只展示一次。回填与机器核验分离，自动或人工回填后仍需重新审核，不由前端直接改变机器结论。

### R3 车型精确查询

侧栏按 **固定页面品牌、车辆类型和车系 → 材料型号 → 全部候选 → 人工选择 → 车型预览及回填** 操作。三个固定条件来自业务页当前选值，必须核验真实 ID；`typeLevel` 只取车源基础信息，不取行驶证完整类型。车系使用业务 `series_id`，不能用内部 `s_id`/车系行 ID 替代。侧栏没有车系下拉或清空范围功能，也不再查询品牌/车系列表。

原生 select 读取选中 option；Ant 控件读取对应 ASelect 的选中值、fieldNames 及显示标签，车系值字段必须是业务 `seriesId`。远程选项未加载时当前 ID 与标签仍可用于范围校验；已加载的同 ID 标签与显示不一致则报错。单项读取失败按字段提示；品牌、车系或基础类型缺失阻止查询，车型未加载不阻止查询。没有完整原页面选择快照不能回填。查询前后重读三个固定条件，任一变化或记录身份变化均丢弃结果。

两个型号分别可选，均填时 AND 精确匹配，只填一个仅限制该型号，均空时浏览固定页面范围，接口及侧栏均不分页。默认值仅来自后端判定可靠的图片证据：整车型号取材料完整型号，去掉品牌汉字；仅根本未提供辅助型号时使用行驶证图片型号。发动机取登记证/铭牌，不从页面参数回退。保留完整后缀，不用号码、马力或模糊型号替代。VIN 不参与搜索条件；行驶证与辅助整车型号不同仍保留辅助整车型号供人工判断。对应型号自身存在多种冲突读值或识别不确定时不任取一值，并保留原因和原图。

范围有效且至少取得一个可靠型号时自动查询。人工修改后不被迟到识别覆盖；恢复材料型号时采用最新材料值。手动搜索可以清空两个型号浏览当前范围。零条、一条、多条都是正常结果，一条也不自动选择；同名不同 ID 分别展示，由审核员核对车型后选择。

扩展调用审核服务 `POST /api/review/vehicle-models/search`：

```json
{"pageScope":{"brandId":"6","brandName":"东风商用车","seriesId":"7235","seriesName":"示例车系","typeLevel":"牵引车"},"announcementModel":"DFH4250A4","engineModel":"DCI450-51"}
```

审核服务返回 `{candidates:[{modelId,modelName}]}`，候选只包含车型 ID 和名称，不再获取或要求规格 `config`。重复/无效车型 ID、空名称及请求失败均作为错误，不当作无候选。

业务接口已知请求字段为 `brandId`、`serialId`、`typeLevel`、`announcementModel`、`engineType`；审核服务内部的 `pageScope.seriesId` 映射为 `serialId`，内部搜索字段 `engineModel` 映射为 `engineType`。接口尚未提供，实际地址、鉴权、成功码及列表外层包装需待真实接口联调。现有 HTTP 适配入口保留 `REVIEW_VEHICLE_API_BASE_URL` 下的 `POST /vehicle-model/review/search` 和 `code=0,data=[...]` 解析，属于待核对的接入约定，不代表业务接口已经可用。未配置或调用失败时明确提示，不注入模拟候选。

业务接口负责提供固定范围内的候选。车源车型查询不访问本地四张 `forj_` 副本、`ref_vehicle_model_key` 或 `ref_engine_emission`，不作本地数据兜底。运行配置见[本地开发](../开发/本地开发.md)。

### R4 仅回填车型与业务页面联动

人工选择具体 ID 后只预览车型变更，先核验固定品牌、车系、车辆类型和完整选择快照。车型必须按实时真实 ID 唯一选择，不能点同名首项。目标选项暂缺可以有限等待，重复、禁用和页面变化立即停止。同 ID 名称有别名时使用实时选项标签核验。预览按真实 ID 统计变更，同名不同 ID 仍计为变更。

助手仅选择原页面车型控件并触发正常选择事件，随后回读车型 ID。驱动形式、燃料种类、排放标准、最大马力、发动机品牌、发动机型号和货箱长度均交给原业务系统联动处理；助手不逐项写入、不恢复旧值，也不因这些参数为空或控件缺失阻止车型回填。助手不请求车型详情接口，也不再以观察业务页面某个固定详情请求作为车型写入的成功条件。

新生成的动作映射仅含车型。已有发布的映射及摘要保持原样，车型处理器执行时只消费唯一有效的车型名称/ID映射，旧品牌、车系、规格和货箱映射均不执行。品牌、车系和类型仍作为实时页面前置条件核验，不能通过旧映射改写。正式配置的后续精简仍须走预览、验证和确认发布。

回填前重新调用候选业务接口，确认所选 ID 仍存在且名称未变化；否则要求重新搜索。写入后核验车型真实 ID、品牌、车系和车辆类型，只有本记录仍有效才更新车型读值及本地选择基准。中断、身份不明或额外变化明确反馈，不能对替换记录恢复或报告成功。已核验车型 ID 的受控变更可更新本地基准以支持重试。

成功提示仅表示“车型已回填并核验”，并提醒核对业务页面自动带出的参数；业务页面参数加载失败或仍在加载不由助手伪装成规格已核验。车型仍需人工确认，重新审核不会因为页面名称相同自动通过。

## 5. 回填与人工边界

普通行驶证字段走统一回填；车型仅走候选选择和车型回填操作，两个搜索型号不能直接回填成车型名称。没有可信候选的值可以核对原图后人工处理，不能用不确定 OCR 自动写入。

查询中、无匹配、范围歧义、车型映射无效和通信错误分别显示；手动修改条件清空旧候选/选择，不被迟到识别覆盖。字段切换保留同条件查询，页面身份或范围变化立即作废。全部候选保留具体 ID，并提供完整预览。

可信候选由扩展后台按标签页/页面实例/记录指纹/采集批次保存，不能接受侧栏任意自带车型对象作为写回依据。后台在目录查询前后向原业务主页面重读范围，核对本次采集身份和 `pageModelScope`，侧栏范围不一致则拒绝；材料筛选不能改变固定品牌、车系与车辆类型。原页面 `pageSelection` 保留品牌、车系、车型 ID/名称及类型快照，回填前再次核验；同名不同 ID 也判定页面变化。已确认的本次写入更新本地读值基准，新的采集建立新基准。页面失效不恢复到其他记录，不点击业务提交。

## 7. 维护约定

字段增删或来源变化同步更新本页矩阵、规则依赖与对应验证。已有能力内改配置，新算法、控件和外部接口由开发扩展。发布后重新采集，核对服务实际加载；历史版本保留用于回滚。
