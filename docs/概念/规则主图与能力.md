# LangGraph 主图与能力

所有审核页面共用一张主图。页面配置决定字段、材料、证据映射、规则和操作边界；主图负责生命周期。普通页面调整使用[声明式配置](../指南/声明式页面配置.md)，不复制流程图，也不向前端加入审核规则。

## 当前执行顺序

主图有 19 个正常流程节点和一个输入错误节点，定义在 `runtime/workflow/graph.py`：

```text
START
  → resolve_context
  → validate_input
       ├─ 无效 → build_error_response → END
       └─ 有效 ↓
  → assess_coverage
  → plan_input_capabilities
  → execute_input_capabilities
  → extract_evidence
  → assess_evidence_quality
  → plan_capabilities
  → execute_evidence_validation
  → execute_evidence_capabilities
  → execute_pre_compare
  → compare_fields
  → execute_post_compare
  → execute_final_review
  → assemble_facts
  → record_degradation
  → prepare_review_tasks
  → derive_recommendation
  → build_response → END
```

`resolve_context` 保留服务已解析的请求与 Profile，页面选择不是由模型临时决定。`validate_input` 校验请求身份、版本、地区及路由，无效请求立即结束正常审核。

报废置换的上传完整性沿用 `assess_coverage` / `assess_evidence_quality`，在 `material_completeness.presence` 提供独立投影；URL 任务在逐图结果合并后更新同一投影。`document_classifications` 保存字段提取前确认的类型和身份证面别，字段失败不抹除分类事实。原 `status` / `checklist` 继续表达证据质量；主图不增加节点。规则、兼容范围和回滚见[报废材料完整性改造](../参考/报废材料完整性改造.md)。

`assess_coverage` 检查采集清单；`assess_evidence_quality` 检查实际识别出的类型、数量、页码、字段来源和不确定信息。上传了一张图不等于它包含所需证据，两个检查不能合并。

流式 URL 作业进入最终主图前已完成图片识别，`extract_evidence` 直接复用初始批次，不重新调用模型。此时输入阶段位于最终主图的提取节点之前，不表示能够追溯阻止此前已发生的识别。

## 能力阶段

| `CapabilitySpec.stage` | 主图节点 | 含义 |
| --- | --- | --- |
| `INPUT_COVERAGE` | `execute_input_capabilities` | 提取节点前的输入检查，可读页面值和采集完整性 |
| `EVIDENCE_VALIDATION` | `execute_evidence_validation` | 识别后检查；内置 `material_completeness` 在这里汇总完整性 |
| `EVIDENCE` | `execute_evidence_capabilities` | 外部核验与证据补全，例如报废证明二维码 |
| `PRE_COMPARE` | `execute_pre_compare` | 产出或检查字段比较需要的事实 |
| `POST_COMPARE` | `execute_post_compare` | 读取比较结果，执行日期、车型等业务规则 |
| `FINAL_REVIEW` | `execute_final_review` | 读取比较结果、前序检查及事实，执行最终复核 |

阶段与事实依赖共同决定执行顺序。输入阶段先独立规划；识别完成后重新规划后续能力，保留输入阶段结果。同一能力在一次图运行中只执行一次，结果逐阶段累积。

内置材料汇总已从 `INPUT_COVERAGE` 迁到 `EVIDENCE_VALIDATION`。自定义 Python Profile 若沿用旧标记，应按实际职责调整。

## 统一证据流

`evidence/collection.py` 统一收集材料识别、页面值、二维码官网值和注册能力输出，供能力上下文、字段比较和事实汇总消费。字段裁决位于 `evidence/comparison/review.py`，不依赖 API 响应组装。

- 只有 `SUCCEEDED` 能力在 `output_facts` 声明的字段，才进入能力证据集合。
- 来源固定为 `capability`，来源 ID 固定为能力 ID。处理器不能将查询结果伪装成页面或图片来源；提取批次中的伪造能力来源也被排除。
- 冲突值和不确定标记保留；失败、没有实际输出或仅有计划产出，均不能满足下游事实依赖。
- 普通比较可使用能力证据；权威链字段必须显式声明 `source="capability"` 才纳入该来源。能力证据不自动替代要求多类图片互证的材料。
- 用于字段比较的证据必须在 `compare_fields` 前产出。启动时拒绝在后置或最终复核阶段声明比较字段输出；后阶段返回二维码字段也按能力失败处理，避免新证据与旧比较结果不一致。
- 后置阶段可产出供最终复核使用的中间事实，如 `post.verified`，与比较证据一并进入最终 `evidence_facts`。

规则通过 `RuleExecutionResult.evidence` 返回事实；外部核验可在返回元组中提供 `EvidenceFact`，均需声明 `CapabilitySpec.output_facts`。能力上下文同时提供 `observations`、`comparisons`、前序 `checks` 和材料完整性。

## 内部状态与响应

`ReviewState` 分别保存观察值、比较结果、检查、完整性、能力计划及结果、动作候选、任务和建议。正常中间节点不构造或读取 `ReviewResponse`。

`assemble_facts` 只汇总证据，不执行规则；`record_degradation` 汇总所有阶段的阻塞与失败；`derive_recommendation` 根据检查和任务生成建议。只有 `build_response` 或输入错误分支生成协议响应。

流式进度接口仍可独立生成部分响应，复用证据收集与比较入口，不运行最终业务能力，与主图中间状态独立。

## 装配与扩展位置

| 位置 | 职责 |
| --- | --- |
| `businesses/configuration/` | 普通页面 JSON 契约、编译、版本快照 |
| `businesses/rules/catalog.py` | 业务处理器、必要字段、检查项、默认阶段 |
| `businesses/external_check_catalog.py` | 外部核验目录，客户端由运行时注入 |
| `businesses/page_action_catalog.py` | 页面动作提议和可写边界声明 |
| `businesses/profile_validation.py` | 地区政策归属和证据阶段校验 |
| `runtime/workflow/capability_assembly.py` | 连接目录、注册表与能力子图 |
| `runtime/workflow/graph.py` | 通用生命周期与调度，不登记具体业务 ID 或字段 |

报废置换页面启用材料完整性、二维码、地区政策、主体关系和所有人等检查。车源旧配置清除后已按新版重新启用普通行驶证比较、品牌型号补全和人工车型搜索，见[车源审核](../业务/车源审核.md)；过户与一致性审核保持未配置的人工复核入口。

规格字段为 `capability_id`、`kind`、`version`、`stage`、`input_facts`、`output_facts`、`required`、`dependencies`、`timeout_seconds`、`retries`、`failure_policy`。绑定提供 `enabled`、`required` 覆盖及 `parameters` 元数据；通用上下文不会自动执行参数代表的业务逻辑。

## 失败与执行限制

注册表只执行 READY 项，按声明进行超时、重试和异常隔离。必需依赖缺失会阻塞，可选依赖缺失会跳过。所有阶段的失败原因都进入最终人工复核依据，后阶段成功不能覆盖前面的失败。

能力当前按依赖顺序串行执行。图片并发由公平调度器负责，最终主图有独立并发限制。子图目前是 `START → execute → END` 的统一能力边界，出现实际内部多步流程时再拆细。

审核作业仍为内存任务，服务重启不能恢复。审核图显式关闭 checkpoint 继承，避免被持久配置图回放时保存内部回调。独立配置服务具有自己的 SQLite 会话、持久 checkpoint、请求幂等和聊天暂停恢复，不改变审核作业生命周期。

配置图包含 `load_context`、`reason`、`execute_tools`、`await_user`、`await_browser`、`verify_candidate`、`await_confirmation`、`commit_configuration`；页面、材料和字段差异由草稿与工具处理，未复制审核主图。节点只保存会话引用和路由，配置事实由会话库拥有，详见[聊天配置指南](../指南/聊天审核配置Agent.md)。

## 验证与边界

架构检查禁止证据层依赖响应呈现，禁止主图导入具体业务处理器或嵌入内置业务登记。回归覆盖真实主图顺序、能力证据匹配/冲突/不确定/失败、来源隔离、跨阶段事实和检查传递、后阶段失败及旧业务动作。

前端负责采集、展示和受控页面操作。材料完整性、字段比较、业务规则、能力调度和审核建议均在后端执行。
