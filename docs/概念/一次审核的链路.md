# 一次审核的链路

扩展采集字段、图片地址及分组，经 POST /api/review/jobs/urls 一次提交；二维码内容优先由同一次 URL 模型提取的 `qr_codes` 提供，模型没有可靠结果时才对二维码候选图片 URL 在内存中执行 ZXing、OpenCV 兜底解码；后端随后做官网域名、HTTPS、访问及字段核验。普通图片不下载、不裁剪、不上传；二维码读取失败或官网不可用时明确转人工复核。

```text
DOM 页面字段、图片 URL
  → URL 任务：校验图片标识和 HTTP(S) 来源
  → 公平调度：全服务 16 路、单任务最多 8 路（生产配置）
  → 已知材料专属提取；未知材料先分类再提取
  → 返回材料字段和证据区域
  → 必要时原图 URL 重读：提示指定字段和归一化区域
  → 复用 AgentBatchResult 完成最终规则汇总
  → GET 轮询任务，扩展最长等待 120 秒
```

二维码内容优先复用模型 `qr_codes`；没有可靠结果时使用二维码专用的内存读取器（ZXing 优先、OpenCV 兜底），不写盘、不上传、不无限重试，且把来源与失败原因返回工作台。

以下是识别结果进入统一主图后的处理顺序：

```text
└─ ◆ 最终汇总  ReviewJobManager._finalize_async
  在独立 finalize 调度器上执行（全局 2 / 单任务 1）
      ★ 复用已识别的 AgentBatchResult，不重新调图片模型
      │
      └─ ◆ 统一主图  ReviewWorkflow.run（19 个流程节点 + 1 个错误节点，所有业务共用）
         │
         ├─ validate_input
         │     校验失败 → build_error_response → END（不执行任何能力）
         │
         ├─ assess_coverage / plan_input_capabilities / execute_input_capabilities
         │     采集完整性和 INPUT_COVERAGE；URL 任务此时已完成单图识别
         │
         ├─ extract_evidence       已复用批次，不再次识别
         ├─ assess_evidence_quality 识别阶段材料确认（页码、字段来源）
         │
         ├─ plan_capabilities      按 Profile 声明 + 实际材料决定跑哪些能力
         │     ★ 单张材料缺失不会阻止不依赖它的能力运行
         │
         ├─ execute_evidence_validation / execute_evidence_capabilities / execute_pre_compare
         │     阶段：EVIDENCE_VALIDATION / EVIDENCE / PRE_COMPARE
         │     ├─ material_completeness  材料是否齐全、页码是否够
         │     └─ scrap_certificate_qr   报废证明二维码核验
         │           ├─ 二维码来源：模型 qr_codes；为空时 ZXing → OpenCV 内存兜底
         │           ├─ 核验：★ 官网域名白名单硬编码；http 升级为 https；保留证书校验
         │           └─ 失败不自动通过，按失败策略转人工
         │     结果逐阶段保留，最终统一记录各阶段降级
         │
         ├─ compare_fields         ★ 审核结论从这里开始
         │     ├─ 页面值、材料识别值、二维码官网值、已声明的成功能力输出 → 统一成 FieldObservation
         │     ├─ 按字段策略过滤掉不允许的材料类型（未知材料不冒充来源）
         │     ├─ 声明了权威链的字段：链首是唯一基准，其余来源按各自窗口比对
         │     │     链首缺失 → 人工复核，不让位给下一条来源，也不退化成投票
         │     ├─ 其余字段：归一化后集合相等即 MATCH，否则 CONFLICT
         │     ├─ ★ 相同材料的相同读值去重，不同读值全部参与裁决；页面值不能筛选证据
         │     └─ ★ 不确定性一票否决：模型说过看不清 → 转人工
         │           已重读过 → 理由里写明「已重读仍无法确认」
         │
         ├─ execute_post_compare / execute_final_review
         │     阶段：POST_COMPARE / FINAL_REVIEW
         │     ├─ 地区政策：发票日期窗口、交车截止日、新车发票产地
         │     ├─ 挂靠主体关系：个人/公司的证据齐备性与主体一致性
         │     └─ verify_invoice：发票号与页面一致时提出「一键验真」页面动作
         │           ★ 只提出动作、不执行；不产出检查项，不占工作台待处理计数
         │
         ├─ assemble_facts / record_degradation
         │     只汇总事实和所有阶段的失败，不再执行规则
         │
         ├─ prepare_review_tasks
         │     日期政策并入对应字段卡；挂靠主体关系合并辅助任务；材料问题汇总成一张卡
         │     ★ 识别诊断留在后端，不通过任务理由泄漏到工作台
         │
         ├─ derive_recommendation ★ 只要有一条 finding 就是 REVIEW_REQUIRED，否则 PASS
         │     没有打分、没有阈值、没有加权、没有投票（平均置信度只用于展示，不参与决策）
         │
         └─ build_response        把页面动作意图一并写回响应

◆ 浏览器适配器执行 page_actions
  后端只提议（action_id + payload），执行与否、如何执行由前端决定
  自动执行只接受显式 requires_authorization=false 的动作，同批按动作 ID 去重
  写回必须：身份校验 → 白名单 → 控件唯一性 → 原值校验 → 写入 → 回读 → 失败回滚



```

审核工作台直接展示原图地址；证据区域使用整张原图的归一化坐标。

接口、并发、取消、进度和迁移说明见[审核流水线](审核流水线.md)。
