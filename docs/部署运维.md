# 部署运维

## 交付范围和目录

服务器只运行审核后端（26101），审核扩展安装在使用者浏览器。配置后端（26102）、配置工作台（26198）留在本机；26199 仅供扩展界面开发预览。所有后端共用服务器 PostgreSQL 的 `forj_review.public`，账号为 `postgres`。

| 位置 | 内容 |
| --- | --- |
| 本机 `release/server/` | 只存放后端压缩包，日常打包不生成其他文件 |
| 本机 `deploy/server/` | 直接保存首次部署固定脚本及模板，无需生成，日常打包不更新 |
| 本机 `release/server/forj-review-server.tar.gz` | 日常更新唯一需要上传的文件，每次打包覆盖生成 |
| 本机 `release/extension/` | 给浏览器安装的扩展 ZIP，无需上传服务器 |
| 服务器 `/home/ubuntu/forj-review/` | 应用包、启停脚本、模板和私密配置 |
| 该目录 `.runtime/` | 当前运行 Compose、发布锁、成功版本和回滚记录，脚本管理 |
| 该目录 `logs/`、`deploy.log` | 应用日志和部署日志，自动轮转 |
| 服务器 `/opt/postgres/` | 共享数据库实例的安装配置，独立于应用更新 |

`deploy/Dockerfile` 用于构建镜像，`deploy/server/` 中的固定脚本、Compose 和模板可直接上传。本文维护完整部署流程，固定目录 README 提供简要入口。不上传本机开发环境的 `.env`、源码、依赖、缓存或 `.idea`。服务器专用的 `.env` 和 `.env.database` 如在本机编辑，可保存在 `deploy/server/` 下；它们被 Git 忽略，需要单独传输，不进入后端压缩包。

固定脚本和 Compose 首次上传后长期保留在服务器。普通代码更新只替换后端包，不重新上传脚本、模板或说明文件；只有实际修改了部署工具、端口映射等配置时，才单独更新对应文件。

### 旧部署名称迁移（仅本次）

如果服务器仍使用 `/home/ubuntu/review-agent-deploy` 和 `start-review.sh`，本次需要迁移固定工具。先在旧目录执行 `./stop-review.sh`，确认旧审核容器已经停止。然后按第 3 节把 `deploy/server/` 内的固定文件和 `release/server/forj-review-server.tar.gz` 上传到新目录 `/home/ubuntu/forj-review/`。

在服务器复制已有私密配置到新目录，仅在目标文件不存在时复制：

```bash
cd /home/ubuntu/forj-review
for name in .env .env.database; do
  if [ ! -e "$name" ] && [ -f "/home/ubuntu/review-agent-deploy/$name" ]; then
    install -m 600 "/home/ubuntu/review-agent-deploy/$name" "$name"
  fi
done
bash setup-server.sh
```

核对这两个文件中的连接参数和密钥后，按第 5 节启动。旧目录及其中日志、回滚记录先保留；新目录从这次发布建立自己的运行记录。共享 PostgreSQL 实例继续使用，无需重建库或重设密码。迁移后，日常更新继续只上传 `forj-review-server.tar.gz`。

本次配置服务前缀改为 `/api/review-config`，扩展地址变量改为 `VITE_REVIEW_API_BASE_URL`。本机配置服务与配置前端须一起重启，并重新打包、加载浏览器扩展；旧客户端不适用于新前缀。两个后端与扩展有更新时保留同版安装文件，回退时恢复同版客户端。审核 API 的 `agent_advice` 等业务字段不变。本机配置服务的状态目录使用 `.review-config/`；已有旧状态目录需先停止配置服务再迁移，不能同时运行两份实例。

## 1. 本机打包

安装并启动 Docker Desktop（Linux 容器），安装 Node.js 22.18+。在 PowerShell 执行：

```powershell
cd D:\fjkj\software\workspace\forj-review
.\scripts\release\package-server.cmd
.\scripts\release\package-extension.cmd
```

`package-server.cmd` 构建 `linux/amd64` 镜像，**只生成一个后端压缩包，不导出任何固定脚本、配置模板或说明文件**。日常打包的输出为：

```text
release/
├── server/
│   └── forj-review-server.tar.gz
└── extension/
    ├── forj-review-extension-public.zip
    └── forj-review-extension-public.zip.sha256
```

服务器包包含镜像、发布标识及 SHA256 校验清单，启动脚本校验后自动解包和加载镜像，无需手动解压。扩展默认连接 `http://175.178.6.214:26101`。需要覆盖地址时，将 `apps/review-extension/.env.public.example` 复制为同目录 `.env.public.local` 并填写 `VITE_REVIEW_API_BASE_URL`。更换服务器地址后重新打包。`package-extension.cmd -Local` 生成连接本机 26101 的扩展。

首次部署文件直接保存在以下目录，不需要执行额外命令，也不会在日常打包时重复生成：

```text
deploy/server/
├── setup-server.sh
├── start-server.sh
├── stop-server.sh
├── rollback-server.sh
├── server-common.sh
├── docker-compose.server.yml
├── review.env.example
├── database.env.example
├── README.md
└── postgres/
    ├── compose.yaml
    └── .env.example
```

服务器初始化后，固定文件长期保留；真实 `.env` 和 `.env.database` 由部署者填写，初始化只创建缺失的文件。已经部署完成时，日常更新只上传后端压缩包。

## 2. 全新 Ubuntu 24.04：准备 Docker

已经安装且能执行 `docker version`、`docker compose version` 的服务器跳过安装，只核对用户权限。服务器不需要 Python、Node.js、Git 或项目源码。

以下安装步骤仅用于没有安装 Docker 的新系统：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
printf 'deb [arch=%s signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu %s stable\n' "$(dpkg --print-architecture)" "$VERSION_CODENAME" | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

授予 `ubuntu` 使用 Docker 的权限：

```bash
sudo usermod -aG docker ubuntu
```

退出 SSH 后重新登录，再验证：

```bash
docker version
docker compose version
mkdir -p /home/ubuntu/forj-review
```

Docker 用户组具备管理宿主机的权限，只给可信部署用户。若已在该组，不必重复退出登录。

## 3. 仅首次：上传固定文件并初始化

首次先执行第 1 节的 `package-server.cmd`。在文件传输工具中，将本机 **`deploy/server/` 里面的固定文件** 和 **`release/server/forj-review-server.tar.gz`** 上传至同一个 **`/home/ubuntu/forj-review/`** 目录，不要多套一层 `server` 目录。

也可在本机 PowerShell 执行（替换地址）：

```powershell
$serverAddress = '你的服务器IP'
ssh "ubuntu@$serverAddress" "mkdir -p /home/ubuntu/forj-review"
scp -r .\deploy\server\. "ubuntu@${serverAddress}:/home/ubuntu/forj-review/"
scp .\release\server\forj-review-server.tar.gz "ubuntu@${serverAddress}:/home/ubuntu/forj-review/"
```

然后在服务器执行：

```bash
cd /home/ubuntu/forj-review
bash setup-server.sh
nano .env
nano .env.database
chmod 600 .env .env.database
```

- `.env`：填写 `DASHSCOPE_API_KEY`，按需要修改模型端点、型号。缺少密钥时不能执行正常材料识别。
- `.env.database`：填写现有数据库 `postgres` 账号的 `PGPASSWORD`；默认连接 Docker 内网 `postgres:5432/forj_review`。
- 密码或 Key 含 `$`、`#`、空格时，在 Compose 环境文件中使用单引号包裹值；密码自身包含单引号时按 Compose 环境文件格式转义。
- `setup-server.sh` 可重复执行，已有密码文件不会覆盖；不会安装或清空数据库。

模板与真实配置分开。首次填写后，脚本、Compose、`.env` 和 `.env.database` 均长期保留在服务器，日常更新不再上传或初始化。

## 4. 核对现有数据库

当前共享数据库已经恢复，应用更新继续使用它。先检查：

```bash
docker ps --filter name=postgres
docker exec postgres pg_isready -h 127.0.0.1 -U postgres -d forj_review
docker network inspect postgres_network --format '{{range .Containers}}{{println .Name}}{{end}}'
```

最后一条的输出应包含 `postgres`。如果容器正在运行但未加入该网络，执行一次：

```bash
docker network connect postgres_network postgres
```

可在数据库客户端中检查已有业务结构：

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
ORDER BY table_name;
SELECT count(*) FROM public.engine_emission_standards;
```

业务库现有 18 张表；发动机参考表初始导入 3,123 条，日常维护后数量可能变化。应用启动只检查已有结构，**不创建业务库、不建表、不恢复业务数据**。

### 仅供数据库也尚未安装的新服务器

**已有 `postgres` 容器或数据卷时跳过本段。** 将交付目录 `postgres/compose.yaml` 与 `.env.example` 作为实例安装源：

```bash
sudo install -d -o ubuntu -g ubuntu -m 0750 /opt/postgres
install -m 644 postgres/compose.yaml /opt/postgres/compose.yaml
# 仅在 /opt/postgres/.env 不存在时创建模板
if [ ! -e /opt/postgres/.env ]; then
  install -m 600 postgres/.env.example /opt/postgres/.env
fi
nano /opt/postgres/.env
cd /opt/postgres
docker compose --project-name postgres config --quiet
docker compose --project-name postgres pull
docker compose --project-name postgres up -d --wait --wait-timeout 180
```

填写自己的 `POSTGRES_PASSWORD`。官方镜像仅在空数据卷首次启动时应用该密码；改 `.env` 不会修改已有账号密码。`postgres-data` 保存数据，禁止用 `down --volumes` 当作更新步骤。

全新实例还必须恢复真实业务备份；空 PostgreSQL 实例不能让本项目正常运行。在确认目标不存在同名业务库后创建，再导入可信的 PostgreSQL custom-format 备份：

```bash
docker exec postgres createdb -U postgres -O postgres forj_review
docker exec -i postgres pg_restore -U postgres -d forj_review --no-owner --no-privileges --exit-on-error < /你的备份目录/forj_review.dump
```

仅向新建空库导入。若备份是文本 SQL，则使用 `psql -v ON_ERROR_STOP=1` 而非 `pg_restore`。备份应包含完整业务结构及数据；没有业务备份时先准备正式初始化和目录数据，不拿测试夹具冒充生产恢复。数据库说明见仓库 `docs/数据库设计.md`。

旧备份若不包含发动机参考表，在本机已有数据库连接下运行：

```powershell
.venv/Scripts/python.exe -m forj_review_service.interfaces.engine_emissions --apply --report .tmp/engine-emissions-import.json
```

此命令显式重建参考映射，源车型目录需先恢复完整。具体见仓库 `docs/发动机排放对应表.md`。

## 5. 启动与浏览器安装

```bash
cd /home/ubuntu/forj-review
./start-server.sh
curl --fail http://127.0.0.1:26101/health
docker ps --filter name=forj-review-service
```

健康检查返回 `{"status":"ok"}`。应用端口映射 `26101:26101`，容器开机自动启动。26102、26198 和 26199 不需要在服务器开放。

云防火墙/安全组允许审核使用者访问 TCP 26101，SSH 22 仅允许管理来源。数据库默认只发布 `127.0.0.1:5432`，审核容器经 Docker 网络访问。已有本机直连保持原配置即可，不需要项目隧道脚本。若确需新开直连，在数据库 Compose 中将监听地址改为服务器地址，并在云防火墙仅允许本机固定公网 IP `/32` 访问 5432；禁止对所有来源开放。跨公网数据库连接应配置 TLS，再在本机使用 `PGSSLMODE=verify-full` 及受信任 CA；不要把默认内网模板误当成公网 TLS 配置。

把 `release/extension/forj-review-extension-public.zip` 解压到本机固定目录，在 `chrome://extensions` 或 `edge://extensions` 启用开发者模式，加载解压目录。随后刷新业务网页。扩展不是服务器上的网页，不上传服务器，不运行 26199 前端服务。

## 6. 日常更新、停止和回滚

本机执行第 1 节的两条打包命令。服务器停止旧应用：

```bash
cd /home/ubuntu/forj-review
./stop-server.sh
```

本机只上传下面这一个文件，覆盖服务器同名包：

| 本机文件 | 服务器目标文件 |
| --- | --- |
| `release/server/forj-review-server.tar.gz` | `/home/ubuntu/forj-review/forj-review-server.tar.gz` |

可以使用文件传输工具，也可在本机 PowerShell 执行：

```powershell
$serverAddress = '你的服务器IP'
scp .\release\server\forj-review-server.tar.gz "ubuntu@${serverAddress}:/home/ubuntu/forj-review/forj-review-server.tar.gz"
```

上传完成后，在服务器执行：

```bash
cd /home/ubuntu/forj-review
./start-server.sh
```

日常流程固定为“打包 → 停止 → 只上传后端包 → 启动”，无需重新上传脚本、执行初始化、设置脚本权限或填写密码。后端更新不会自动更新浏览器扩展；扩展有改动时，用新 ZIP 替换本机解压内容并在扩展管理页点击重新加载，再刷新业务页。

脚本保存上一成功版本的镜像和匹配 Compose；重复启动同一版本不覆盖真正的上一版。失败时检查日志，需要回滚则执行：

```bash
cd /home/ubuntu/forj-review
./rollback-server.sh
```

回滚仅切换应用镜像及 Compose，不恢复数据库或密码。保留 `.runtime/` 和回滚镜像。首次部署无上一版本可回滚。

## 7. 日志、备份与配置发布

```bash
cd /home/ubuntu/forj-review
tail -n 100 logs/review-service.log
tail -n 100 deploy.log
docker logs --tail 100 forj-review-service
curl --fail http://127.0.0.1:26101/api/review/configuration/loaded
```

应用日志按天或 10 MiB 轮转，默认最多 30 份归档；容器日志 10 MB × 3；部署日志超过 5 MiB 后下次操作轮转，保留上一份。`trace_id` 关联模型、流程与结论，`job_id` 定位任务。日志不保存材料原值、模型原文和密钥。

备份共享业务库，在服务器执行：

```bash
mkdir -p /home/ubuntu/database-backups
chmod 700 /home/ubuntu/database-backups
(umask 077; docker exec postgres pg_dump -U postgres -d forj_review -Fc > "/home/ubuntu/database-backups/forj_review-$(date +%Y%m%d-%H%M%S).dump")
```

确认命令成功并保留服务器之外的副本。数据库备份与应用打包独立。

本机配置工作台保存页面配置后，重启服务器审核服务加载新快照。离线导出、回放、发布和版本核对统一见仓库 `docs/审核配置开发.md`。

| 问题 | 检查 |
| --- | --- |
| Docker 权限不足 | `docker info`、用户组、是否重新登录 |
| `network postgres_network not found` | 先执行 `setup-server.sh`，再核对数据库网络 |
| 数据库读取失败 | 容器、网络、密码、`forj_review.public` 的已有结构 |
| 日志无法写入 | 使用 `start-server.sh`，它准备容器用户写权限 |
| 扩展连接失败 | 发布地址、26101 安全组、健康检查、重载扩展并刷新页面 |
| 识别不可用 | `.env` 中的模型 API Key、端点、额度和限流 |
| 新配置未加载 | 重启后端，核对 loaded 接口，再重新采集业务页 |
