# 部署运维

## 交付范围

服务器只运行独立审核后端，浏览器安装审核扩展。没有审核配置工作台、配置服务、数据库容器或迁移步骤。四个审核页面规则及排放参考 JSON 在镜像内，随镜像一同更新和回滚；不挂载数据库目录。

| 位置 | 内容 |
| --- | --- |
| `deploy/server/` | 首次部署固定脚本、Compose、环境模板和说明 |
| `release/server/forj-review-audit-server.tar.gz` | 日常更新的单个后端压缩包 |
| `release/extension/` | 浏览器扩展 ZIP 和摘要 |
| `/home/ubuntu/forj-review-audit/` | 服务器应用目录 |
| 应用目录 `.runtime/` | 当前 Compose、部署锁、成功镜像与回滚记录 |
| 应用目录 `.env` | 服务器自己的模型与业务接口参数 |
| 应用目录 `logs/`、`deploy.log` | 自动轮转的应用和部署日志 |

镜像为 `forj-review-audit:master`，容器名为 `forj-review-audit`，Compose 项目名为 `forj-review-audit`。默认映射 26101。与原服务并行时在 `.env` 设 `REVIEW_HTTP_PORT=26103` 等可用端口，执行脚本时同步设置 `REVIEW_HEALTH_URL=http://127.0.0.1:26103/health`；扩展也需构建到此地址并明确添加对应主机权限。

## 本机打包

启动 Docker Desktop（Linux 容器），在本项目运行：

```powershell
.\scripts\release\package-server.cmd
.\scripts\release\package-extension.cmd
# 本机服务扩展：
.\scripts\release\package-extension.cmd -Local
```

后端打包构建 Linux/amd64 镜像，记录代码修订、未提交状态和镜像 ID，生成包内 `SHA256SUMS`。压缩包仅含 `forj-review-audit-master.tar`、`release.json` 和 `SHA256SUMS`。失败保留之前的压缩包，不改服务器固定文件或密钥。原图、工作区 `.env` 和测试内容不会进入镜像。

## 首次部署

服务器需要 Docker、Compose v2、Bash、curl、flock、tar、sha256sum。将 `deploy/server/` 内固定文件与后端包上传到单独的应用目录；不要覆盖原项目的部署目录。执行：

```bash
cd /home/ubuntu/forj-review-audit
bash setup-server.sh
# 编辑 .env，填写模型密钥和可用的车型业务接口参数。
./start-server.sh
```

setup 创建 `.runtime` 和缺失的 `.env`，保留已有密钥；不创建网络、数据库或容器。start 验证包成员、普通文件类型、校验清单和镜像 ID，再用新镜像在禁网条件下校验规则及参考文件，成功后才替换服务。当前部署使用镜像内 JSON；不要把本机 JSON 路径填入服务器 `.env`。如需调整正式数据，在代码中更新、验证并重打镜像。

镜像以 UID 10001 运行，根文件系统只读，`/tmp` 使用临时内存文件系统，仅 `logs/` 挂载为可写。脚本为日志目录准备权限。应用日志按天或大小轮转，数量可配；Docker 标准输出日志单独轮转，部署日志保留有界历史。

## 更新、停止与回滚

普通更新只上传新的后端压缩包，再运行 `./start-server.sh`，不提前停止旧实例。脚本或 Compose 有修改时同步上传相应固定文件。成功发布保留上一版本镜像及配套 Compose；重复启动同一版本不会覆盖真正的上一版本。

```bash
./stop-server.sh
./rollback-server.sh
```

回滚恢复上一镜像和 Compose，包含配套页面规则及排放 JSON，无数据库恢复步骤。不使用 prune 或删除卷。任务仅在内存保留，服务重启后在浏览器重新采集和审核；原业务系统保存的内容不受影响。

## 检查和排障

- `/health` 检查进程就绪；`/api/review/configuration/loaded` 返回内存中实际页面版本、指纹和 `configuration_source=json`。
- 缺失、损坏或不一致的 JSON 会阻止启动；不要以空文件或测试夹具兜底。
- 车型接口未配置时明确不可用；模型密钥缺失时显示材料未完成，不能视为审核通过。
- 核对 `logs/review-service.log`、`deploy.log` 及 Docker 日志中的错误类型和 trace_id，不在公开输出中记录密钥、材料或签名 URL。
- 并发与识别预算沿用现有审核机制，配置说明见 `review.env.example`。日志完整不代表识别成功或审核通过。

构建后可用 `uv run python scripts/ci/smoke_container.py forj-review-audit:master` 验证禁网运行、各业务入口、日志、权限及正常关闭。此检查不调用真实模型、官网或业务车型服务，也不代替真实浏览器联调。
