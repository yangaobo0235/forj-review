# 本地开发

## 环境与依赖

在仓库根目录执行，需要 Python 3.11 或 3.12、uv、Node.js 22.18+。正常运行连接已经准备好的 PostgreSQL，本机不必安装 PostgreSQL。自动化数据库测试使用 Docker 临时实例。

```powershell
uv sync --locked
npm --prefix apps/review-extension ci
npm --prefix apps/review-config-web ci
```

Python 依赖统一由 `pyproject.toml` 和 `uv.lock` 管理。两个前端分别有自己的 `package.json` 和 `package-lock.json`，根目录 npm 命令负责转发。

## 准备运行配置

已有文件直接保留。首次使用仅在文件不存在时复制模板：

```powershell
if (!(Test-Path .env.database)) {
    Copy-Item .env.database.example .env.database
}
if (!(Test-Path src/forj_review_service/.env)) {
    Copy-Item src/forj_review_service/.env.example src/forj_review_service/.env
}
if (!(Test-Path src/forj_review_config_service/.env)) {
    Copy-Item src/forj_review_config_service/.env.example src/forj_review_config_service/.env
}
```

在编辑器填写数据库连接和对应服务模型密钥。不要把实际 `.env` 或 `.env.database` 加入版本控制、打包或贴到日志中。

| 文件/变量 | 作用 |
| --- | --- |
| 根目录 `.env.database` | 两服务共享的 PostgreSQL 地址、账号和密码，格式见模板 |
| 审核服务 `.env` | `DASHSCOPE_API_KEY`、端点、模型、审核日志等 |
| 配置服务 `.env` | `CONFIGURATION_API_KEY`、端点、模型、样例和配置工作台连接等 |
| `DATABASE_CONFIG_FILE` | 指定另一份私密数据库配置文件 |
| `REVIEW_DATABASE_URL` / `CONFIGURATION_DATABASE_URL` | 各服务显式连接覆盖值 |
| `REVIEW_DATABASE_SCHEMA` / `CONFIGURATION_DATABASE_SCHEMA` | 默认 `public`；两服务共用 `forj_review.public`，仅隔离测试使用其他 Schema |

进程环境变量优先于文件。两个服务只读取自己包下的模型 `.env`，不读取根目录模型 `.env`；相对目录按该 `.env` 所在位置解析。前端 `.env.example` 只放连接地址，不填写模型密钥。

服务启动检查已有数据库结构，不创建数据库或表，也不回退 SQLite。数据库与服务器运行说明集中在[部署运维](部署运维.md)。

四个应用端口固定为：审核后端 `26101`、配置后端 `26102`、审核扩展界面预览 `26199`、配置前端 `26198`。服务器审核端口映射为 `26101:26101`。安装后的浏览器扩展本身不监听 HTTP 端口，`26199` 仅用于界面开发和预览。

本机和服务器连接同一个 `forj_review.public`，客户端使用标准 `PG*` 变量。本机直接连接时，`.env.database` 的 `PGHOST` 填实际数据库服务器地址，`PGPORT=5432`、`PGDATABASE=forj_review`、`PGUSER=postgres`，密码自己填写。若当前连接已经可用，保留已有私密配置。项目不再提供隧道脚本，也不要求运行额外连接脚本。数据库访问范围和 TLS 以实际服务器配置为准，见[部署运维](部署运维.md)。

## 启动与调试

在不同终端按需运行，各进程可独立停止：

```powershell
# 审核服务，默认 127.0.0.1:26101
uv run forj-review-service --reload
```

```powershell
# 配置服务，默认 127.0.0.1:26102
uv run forj-review-config-service
```

```powershell
# 配置工作台，默认 127.0.0.1:26198
npm run dev:configuration
```

```powershell
# 审核扩展界面开发预览，默认 127.0.0.1:26199
npm run dev:extension
```

只使用服务器审核功能时，本机无需启动审核服务。配置工作台通过本机配置服务保存统一的 `forj_review.public` 配置；服务器审核服务重启后加载同一套配置。

构建扩展：

```powershell
npm run build:extension
```

在 Chrome 扩展管理页启用开发者模式，加载 `apps/review-extension/dist`。每次重新加载扩展后刷新业务页，再重新采集。`npm run dev:extension` 是界面预览开发服务器，不能代替实际扩展的构建和加载。

IDEA 中可自行建立 Python 模块运行配置：审核服务使用 `forj_review_service.interfaces.cli`，配置服务使用 `forj_review_config_service.interfaces.cli`，解释器均选择项目 `.venv`，工作目录选项目根目录。前端使用对应应用 `package.json` 的 npm 配置。项目不维护额外的启动包装脚本。

## 不连接数据库的配置检查

```powershell
uv run forj-review-service --check-pages examples/page-config
uv run forj-review-service --inspect-pages examples/page-config
uv run forj-review-service --replay-pages examples/page-config --cases examples/page-config/回放样例/permit-cases.json
```

这些命令使用脱敏固定样例，不启动 HTTP 服务、不调用模型、不发布配置。详细格式见[审核配置开发](审核配置开发.md)。

## 修改后的检查

```powershell
uv run ruff check src tests scripts
uv run python -m compileall -q src
uv run pytest tests -q
uv run python scripts/ci/check_architecture.py
node scripts/ci/check-extension-architecture.mjs
npm run test:extension
npm --prefix apps/review-extension exec playwright install chromium
npm run test:extension:browser
npm run lint:extension
npm run build:extension
npm run build:extension:public
npm run test:configuration
npm run lint:configuration
npm run build:configuration
```

后端测试分为 `tests/unit`、`tests/contracts` 和 `tests/integration`。前两组可直接运行 `uv run pytest tests/unit tests/contracts -q`，不启动数据库；数据库集成夹具才申请独立测试空间。配置服务的数据库测试覆盖事务回滚、并发发布、持锁连接断开、旧执行器写入拦截和事件循环响应。

两个前端统一使用 Vitest，可在应用目录运行 `npm run test:watch`。Vue 组件交互使用 Vue Test Utils 与 jsdom；模块导入和模拟统一由 Vitest 管理。扩展的 `test:browser` 使用 Playwright Chromium 验证原生表单采集、跨分区隔离和回填读回，只访问仓库内合成页面。所有前端测试及浏览器测试均已接入 CI。

需要数据库的 pytest 用例默认通过 Docker 在本机启动临时 PostgreSQL，使用随机测试 schema 并清理。也可通过 `FORJ_TEST_POSTGRES_URL` 指定独立的本机测试实例；测试拒绝远程地址，不读取真实服务器凭据。`tests/support` 的建表代码只服务合成测试，不进入应用镜像。

Python 发行包验证使用 `uv build`；容器验证使用 `uv run python scripts/ci/smoke_container.py 镜像名`。发布流程见[部署运维](部署运维.md)。

## 工作区与文档维护

临时验证文件放 `.tmp/`，构建产物放 `release/` 或前端 `dist/`；这些均不提交。不要清理私密配置、运行状态或数据库备份来解决启动问题。

文档入口集中在根目录 README，各指南只维护自身主题；历史迁移过程通过 Git 追溯，不保留重复部署说明和一次性验收脚本。

IDEA 项目树只应包含当前项目目录；`External Libraries` 是解释器和依赖，`Scratches and Consoles` 是 IDE 草稿入口。如出现整个父目录 `workspace`，检查模块的 Content Root 是否指向 `D:\fjkj\software\workspace\forj-review`，然后重新加载项目。文件颜色表示版本控制状态；未跟踪的源码需要随功能变更纳入 Git，私密 `.env` 继续忽略。
