# 审核辅助使用

## 使用前确认

审核浏览器扩展安装在使用者电脑，审核服务可以运行在服务器。本机开发安装见[本地开发](本地开发.md)，连接服务器的发布扩展见[部署运维](部署运维.md)。

当前业务包括青岛、长春报废置换、车源和过户审核。材料与字段要求以[各业务规则](业务/)为准。一致性审核未配置，不会自动给出通过结论。

## 完成一次辅助审核

1. 打开业务审核详情，等待表单和材料图片加载完成。
2. 打开扩展，确认当前业务、地区及审核步骤。共享地址的页面还需进入正确的激活审核页签。
3. 点击“开始审核检查”。扩展采集当前页面字段和图片地址，由服务执行识别、证据比较和规则检查。
4. 等待识别和汇总完成，查看“待处理”“全部字段”“页面外核验”。材料上传情况单独展示，不代替材料内容审核。
5. 对照页面原始值、材料提取值、来源和理由处理异常。需要时打开原图定位证据。
6. 对允许回填的字段，审查目标值后使用回填或人工输入；等待“已回填并回读”反馈。车型候选必须人工选择，即使只有一条。
7. 根据业务规定完成实际系统中的人工审批。扩展不提交审批、不点击下一步。

普通图片通过 URL 交给模型读取。图片必须有模型能够访问的 HTTP(S) 地址；`blob:`、`data:` 或失效签名地址不能作为正常材料来源。单次最多 16 张图片。

## 怎样理解结果

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 绿色：一致/满足 | 该项现有证据满足规则 | 仍需关注整单其他检查 |
| 红色：冲突 | 可靠证据已证明差异或违反硬性规则 | 核对来源，按业务流程处理 |
| 橙色：待复核 | 材料不足、不确定、缺权威来源、外部核验不可用或政策要求人工确认 | 补充证据或人工确认 |

红色不代表系统已自动驳回，绿色也不代表实际审批已提交。“已处理”只记录工作台操作进度，不修改后端原始结论；待处理数量为零不能代替整单审核判断。

上传完整性与识别内容分开：上传了图片不代表材料页码或内容正确，识别失败也不应抹除已经确认的上传事实。二维码出现官网链接，只表示拿到了地址，官网访问、字段提取和字段一致性仍需逐步核验。

## 回填与页面变化

只有后端声明允许、控件可编辑且扩展支持的字段才提供回填。写入前重新检查记录、采集批次、目标控件和原值，写入后回读；失败时显示原因并在页面身份仍有效时尝试恢复。

切换记录、刷新页面、切换审核页签、替换控件或修改身份锚点后，旧采集可能失效。出现“页面操作已停止”时重新采集并复核，不能继续用旧结果写入新记录。原图定位也会检查页面身份。

车源车型查询取当前品牌、车系、车辆类型、完整整车型号与发动机型号的交集；无候选时核对输入，不自动放宽后缀或搜索全库。选择后规格参数逐项回读，缺少货箱长度时保留页面原值。

## 常见问题

| 现象 | 首先检查 |
| --- | --- |
| `Receiving end does not exist` | 重载扩展后是否刷新了业务页 |
| 连接失败 | 扩展构建地址、审核服务和网络是否正常 |
| 正在识别很久 | 模型可否访问材料地址、模型网络和额度 |
| 部分完成 | 查看失败与超时材料；流程已结束，不表示仍在识别 |
| 页面控件无法回填 | 页面是否变化，控件是否唯一、可编辑及已支持 |
| 新配置未生效 | 核对目标数据库空间，重启审核服务并重新采集 |

任务快照保留约十分钟，服务重启后丢失；系统不长期保存本次审核结果。需要排查时记录非敏感的 `job_id` 或 `trace_id`，按[部署运维](部署运维.md)查询日志。
