# 项目英文术语对照表

本文档统一规定项目中英文专业术语的中文含义。代码中的标识符必须保持稳定，文档和界面在首次出现时使用“英文术语（中文含义）”格式；同一文档后续可以使用简称，但不能自行创造另一种译法。

| 英文术语 | 中文含义 | 在本项目中的具体含义 |
| --- | --- | --- |
| LangGraph | LangGraph 流程图框架 | 用节点和边编排审核生命周期的运行框架 |
| Profile | 业务配置档案 | 某种业务、地区、版本的完整配置 |
| Registry | 注册表 | 通过稳定 ID 查找能力、规则、页面或渲染器的目录 |
| Capability | 审核能力 | 可被 Profile 组合调用的一项独立检查能力 |
| CapabilitySpec | 能力规格 | 能力的类型、阶段、依赖、输出、超时和失败策略 |
| Handler | 处理器 | 实际执行一项能力或规则的函数/对象 |
| Subgraph | 子图 | 在主图内部封装多步领域流程的 LangGraph 图 |
| PageAdapter | 页面适配器 | 把具体网页 DOM 转换为标准页面数据的适配层 |
| PageIdentity | 页面识别声明 | 「管理端审核页地址 → 业务、地区、页面特征」的声明；浏览器据此判定当前页面是哪个业务 |
| page_anchors | 页面特征文案 | 该审核页上必须全部出现的区块标题或字段标签，用于地址认不出来或一个地址挂多个业务时判定页面 |
| page_catalog | 页面识别清单 | `GET /api/review/page-catalog` 下发的全部页面识别声明；识别先于采集清单，因此不按业务类型查 |
| PageAction | 页面动作 | 经授权后对审核页面执行的受控读写操作 |
| page_target_field | 页面定位字段 | 任务在页面 DOM 中定位真实控件所使用的稳定字段键；可与助手展示任务同时存在 |
| page_fill_intent | 页面填写意图 | 后端根据规则给出的受控写回动作集合，包含目标字段、显示标签和允许填写的主体类型 |
| owner_type | 主体类型 | `PERSONAL`（个人）或 `COMPANY`（公司/企业），用于挂靠下拉框的默认选择 |
| MATERIAL-GROUP | 已退役的材料完整性任务 | 当前后端不再生成，旧响应也不展示或计数；材料检查保留在后端诊断和判定中 |
| Renderer | 渲染器 | 把后端审核任务转换为工作台界面的组件 |
| Workbench | 审核工作台 | 展示任务、证据、状态并承载人工操作的界面 |
| Evidence | 证据 | 支持某个字段或结论的页面、图片、二维码或外部来源 |
| EvidenceFact | 证据事实 | 已规范化、可追溯的结构化证据对象 |
| CheckResult | 检查结果 | 一项能力或规则的状态、理由、证据和限制 |
| ReviewTask | 审核任务 | 提供给审核员处理的字段、材料或业务核验事项 |
| ReviewRequest | 审核请求 | 前端提交给后端的版本化请求对象 |
| ReviewResponse | 审核响应 | 后端返回给前端的完整审核结果对象 |
| Review Job | 审核作业 | 可逐张接收图片、公开进度并最终生成审核响应的异步任务 |
| JobStatus | 作业状态 | 表示作业运行中、部分完成、完成、失败或取消的终态语义 |
| ReviewJobPhase | 作业阶段 | 表示上传、识别、最终汇总等当前执行阶段 |
| Fair Scheduler | 公平调度器 | 在全局和单任务并发上限内按任务轮转分配模型槽位 |
| PageData | 页面数据 | 前端从当前页面采集的字段、材料和页面身份信息 |
| Planner | 能力规划器 | 根据 Profile、依赖和材料覆盖决定执行哪些能力 |
| BusinessRegistry | 业务注册表 | 查找业务 Profile 的注册表 |
| CapabilityRegistry | 能力注册表 | 查找并执行能力 Handler 或子图的注册表 |
| BusinessRuleRegistry | 业务规则注册表 | 查找业务规则处理器的注册表 |
| ExternalCheckRegistry | 外部核验注册表 | 查找二维码、第三方接口等外部核验处理器的注册表 |
| PageAdapterRegistry | 页面适配器注册表 | 查找和校验页面适配器的注册表 |
| PageActionRegistry | 页面动作注册表 | 约束可执行页面动作及其权限的注册表 |
| Renderer | 渲染器 | 把后端审核任务转换为工作台界面的组件。前端用 `registerWorkbenchRenderer` / `resolveWorkbenchRenderer` 按 Profile Key 选择，没有名为 `RendererRegistry` 的类 |
| DOM | 页面文档对象模型 | 浏览器中表示网页元素和控件的对象结构 |
| OCR | 光学字符识别 | 从材料图片中提取文字和字段的识别技术 |
| QR | 二维码 | 报废证明等材料中的二维码核验入口 |
| API | 应用程序接口 | 前端与后端交换审核协议的 HTTP 接口 |
| Adapter | 适配器 | 将外部页面或数据转换为内部标准结构的组件 |
| 页面写回校验 | 动作控制器 | 写回前后的身份、权限、唯一性、原值、回读和回滚校验。实现在 `apps/extension/src/platform/browser/actions/page-field-writer.ts` 与 `apps/extension/src/platform/extension/page-action-registry.ts`，没有名为 `ActionController` 的类 |
| Conventional Commits | 约定式提交 | 使用 `feat`、`fix` 等类型描述提交目的的规范 |
| PR / Pull Request | 拉取请求/合并请求 | 请求将分支改动合并到主分支的 GitHub 审查单元 |
| CI / Continuous Integration | 持续集成 | 自动执行测试、检查和构建的流水线 |

## 状态枚举

| 英文状态 | 中文含义 | 展示要求 |
| --- | --- | --- |
| `MATCH` | 一致/满足 | 绿色，同时显示文字 |
| `CONFLICT` | 冲突/不一致 | 红色，同时显示冲突理由 |
| `INSUFFICIENT` | 证据不足/无法校验 | 橙色，进入人工复核 |
| `REVIEW_REQUIRED` | 需要人工复核 | 橙色或警告标记 |
| `PASS` | 建议通过 | 只能由后端整体建议返回 |
| `READY` | 已准备执行 | 能力规划阶段可执行 |
| `BLOCKED` | 被阻断 | 依赖或强制条件未满足 |
| `FAILED` | 执行失败 | 已执行但发生错误 |
| `SKIPPED` | 已跳过 | 按配置或安全降级跳过 |
| `NOT_CONFIGURED` | 未配置 | 没有可用的生产规则或能力 |
| `MANUAL_REVIEW` | 人工复核 | 失败或不确定时的处理策略 |
| `RUNNING` | 作业运行中 | 上传、识别或汇总仍在继续 |
| `PARTIAL` | 作业部分完成 | 作业已结束，但存在失败、超时或未处理材料 |
| `COMPLETED` | 作业完成 | 作业正常完成并生成最终快照 |
| `CANCELLED` | 作业已取消 | 取消排队及运行中的协程，迟到结果不再写回；任务只保存 URL 和结果 |

## 命名原则

代码标识符、协议字段和注册表 ID 使用英文稳定名称；面向审核员的标题、状态、按钮和错误提示使用中文。文档中第一次介绍代码对象时必须同时给出中文解释，例如“`PageAdapter`（页面适配器）负责读取 DOM”，不要只写英文名称。
