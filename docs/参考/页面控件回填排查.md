# 下拉框与日期回填

## 现场根因

长春报废置换审核页使用 Ant Design Vue 控件。文本框可以通过原生值设置和输入事件提交，但另外两类控件有自己的交互协议。

1. 下拉框的 `aria-controls` 指向一个宽高为零的无障碍列表。真正可点击的 `.ant-select-item-option` 是这个列表的兄弟节点，位于同一 `.ant-select-dropdown` 中。旧逻辑只在无障碍列表内找选项，未命中实际组件选项。
2. 单日期控件的内部 `input` 带 `readonly`，表示用户应通过日历选择，而非整个字段不可修改。旧采集器将其识别为不可编辑文本框，写回器也拒绝只读输入。即使直接设置 `input.value`，也不能据此证明 Vue 绑定值已更新。
3. 日期组件通过 `mousedown` 打开日历，通过 `mouseup` 清除值；只调用 `.click()` 无法完整触发交互。真实组件验证复现了这一点。
4. 日历关闭有过渡动画；连续回填必须等待浮层真正隐藏，再打开下一次日历，避免把复用中的浮层误判成其他控件的日历。

车源、过户的旧配置与白名单已清除。长春报废业务没有这个类型限制，不能将其下拉和日期失败归因于白名单。

## 修复边界

- `platform/browser/form-controls.ts` 统一采集器和写回器对逻辑控件类型的判断。单日期选择器内部只读输入允许通过日历编辑；普通只读输入和禁用控件仍拒绝写入。
- `platform/browser/actions/page-field-writer.ts` 从控件关联的列表定位所属下拉浮层，在浮层内优先匹配可见选项。选项文本精确匹配，重复、禁用或不存在的值均停止，不跨下拉框搜索。
- `platform/browser/actions/date-picker.ts` 使用公开 DOM 事件打开日历、切换年月、点击目标日期，再关闭日历并回读。仅接受有效的 `YYYY-MM-DD`，不访问 Vue/React 私有实例。
- 单字段和组合回填共用控件适配器，失败回滚也走相同交互。记录身份失效后停止写入和回滚，避免写到另一条记录。
- 后端配置声明允许的字段、控件类型和页面身份；浏览器平台执行具体 DOM 交互。前端工作台不承担业务审核规则。

支持本次验证的 Ant Design 单日期日历；范围、日期时间、月份选择及其他未适配组件不承诺自动回填。虚拟下拉列表只选择当前已渲染且唯一匹配的选项，没有可靠匹配时提示人工处理。

## 验证

自动化用例覆盖虚拟列表辅助节点与真实选项分离、只读日历、跨年月导航、无效日期、禁用日期、切换失败、记录身份失效及组合回填恢复空日期。

本地使用 Vue 3 和 Ant Design Vue 4.2.6 加载项目真实写回器，验证下拉显示文本对应的字典值确实改变、只读日期提交成功、跨年月选择和恢复成功；每次回填后触发组件重新渲染，检查绑定值仍然保留。测试只使用合成数据，不向实际审核系统提交。

启用新代码需要重新加载扩展并刷新业务页面，再重新采集审核。旧页面中已注入的内容脚本不会随着构建自动更新；后端配置更新需要重启后端。
