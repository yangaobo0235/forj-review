# 审核业务复盘与修正记录

日期：2026-10-13。范围：青岛、长春报废置换、车源、过户审核，以及共用证据聚合、任务调度、二维码、结果展示和页面操作。

本轮以调用链、业务声明、代码引用和回归测试为依据。重点是避免错误通过、遗漏异常、错写页面和废弃任务继续消耗资源。已修正的问题如下；尚需部署信息或独立设计的改进列在后文。

## 3. 尚需优化的真实边界

| 优先级 | 边界与证据 | 下一步 |
| --- | --- | --- |
| 高 | 审核 API 本身未看到应用级鉴权；仓库 Compose 直接映射服务端口。二维码图片读取支持 HTTP(S) 和跳转，没有图片来源域名、私网地址与网络出口限制。官网白名单只限制二维码载荷目标，不能保护图片抓取 | 核对实际网关、防火墙和调用者范围，确定合法图片域名及内网使用场景，再统一落地入口鉴权、限流和出口限制；本轮没有臆设 CDN 域名而改变合法材料访问 |
| 高 | 二维码像素上限在 `cv2.imdecode` 已分配图像后检查；原生线程不能被异步超时强制终止 | 评估解码前尺寸校验与隔离进程的硬超时/内存限制；现有字节、时间、2 槽位限制缓解积压，但不是内存硬隔离 |
| 中 | 服务端无跨请求幂等存储，每次 create 生成新 job；动作去重只覆盖同一最终批次，`trace_id` 只用于追踪 | 设计稳定的请求幂等键、失效范围与结果复用；对有副作用动作另行保存执行状态，不自动把重跑当成安全重放 |
| 中 | URL 模式依赖模型及后端能访问原图；签名过期、登录态图片或网络隔离仍会失败 | 验收真实材料域名、有效期和网络路径，区分访问失败与识别失败；当前显示人工核对/重新采集，不恢复上传压缩链 |
| 中 | 缺少 `document_type` 的旧观察仍有兼容入口，低置信度与语义有效性主要依赖不确定标记和业务规则 | 通过版本化契约逐步收紧来源、字段有效性与不确定标记；不能仅凭相同字符串证明材料可信，也不能用一个全局置信度阈值替代业务声明 |
| 中 | 任务存储是进程内字典，TTL 清理由 create/get 触发；重启后任务消失，且当前没有总体队列/用户配额 | 若扩大并发或使用多 worker，增加任务容量限制与定期清理，明确持久化、跨 worker 路由和重启恢复策略 |

当前构建和回归使用合成材料/模拟 HTTP，没有在真实审核页验证二维码识别率、登录图片访问、运营人员操作和服务器访问控制。上述事实需要现场验收，不应从单元测试推断已经解决。

## 6. 后续工作台调整与回填优化（2026-10-12）

按操作人员最新要求，青岛、长春、车源和过户字段工作台取消顶部“Agent 最终审核建议 / 建议人工复核”大卡片，统一隐藏材料完整性汇总并排除相关计数。该要求替代第 2 节所记录的材料异常及整体建议展示方案；后端规则和最终建议继续保留，工作台仍使用“展示项目已处理”而非“整单审核通过”。旧版结果 Renderer 仍有调用，相关建议和材料组件不是死代码。

“回填此值”通过浏览器消息执行，不调用模型或后端。排查发现身份守卫反复执行完整表单采集，重建审核目录并匹配全部字段；正常身份校验失败后的目标字段替换校验还会再次采集。现改为实时采集清单中的身份锚点，同一次校验复用一份样本，避免全量目录生成和非身份字段匹配。别名索引只缓存定义，清单替换时重建，不缓存页面值或歧义结果；重复控件、独立强身份锚点、原值、回读和回滚检查保留，框架更新等待保留。

新增测试覆盖四个已注册工作台无建议卡片、隐藏材料计数、稀疏采集与完整采集的一致性、实时值变化、重复身份控件、只读及表格锚点、清单替换后的索引刷新，以及单次回填仅初始审核做完整采集、每次守卫只读取一次身份样本。扩展全量测试 315 通过，eslint、TypeScript、公开版及开发版构建通过，最终 `dist` 保留开发版。此次没有改动后端；真实审核页的耗时及加速幅度尚未测量。更新扩展后须刷新业务网页，让新版 content script 生效。

## 7. 连续组合回填后原图定位失效（2026-10-13）

新车车架号组合回填同时写入 `new_vehicle.vin` 和 `page_ocr.new_vehicle_vin`。第二次成功回填曾把身份记录的 `original` 覆盖为第一次回填后的值；原图定位用该记录还原页面指纹，因此与最初采集指纹不一致，误报“页面已变化”。单字段和组合字段现在使用同一记录入口，保留本采集批次第一次回填前的值，只更新最新已回读值；重新采集仍清空旧记录。未受控的锚点修改和真正换单继续拒绝原图定位。

回归测试先复现失败，再验证同值连续回填、不同候选切换及回到初始值、单字段与组合字段交替、初始 VIN 为空、手动改 VIN、申请编号变化和重新采集。扩展全量测试 319 通过，eslint、TypeScript 及公开版/开发版构建通过；公开安装包已更新。此次未提交代码，未改动后端。
