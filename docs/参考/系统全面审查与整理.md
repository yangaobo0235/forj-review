## 结论与框架定位

当前结构可以继续作为本地审核业务底座，不需要再整体重构。两个前端均为 Vue 3 SFC + TypeScript，未保留产品源码中的 React、JSX 或 TSX 入口；测试和构建脚本中的 JavaScript 属于开发工具。两个前端分别持有样式和状态，只共享纯类型契约。

| 模块 | 应承担的职责 | 普通页面变更是否需要修改 |
| --- | --- | --- |
| `apps/extension` | DOM 采集、图片/字段定位、受控回填、配置试采集 | 使用已有采集与控件能力时不需要 |
| `apps/configuration-web` | 范围选择、聊天展示、验证结果、确认交互 | 不需要 |
| `src/forj_configuration_agent` | 模型工具循环、会话、草稿、歧义询问、完成条件、受控保存 | 不需要复制 Agent 主图 |
| `src/forj_review_assistant` | 配置编译、证据裁决、业务规则、审核主图、能力执行 | 已有比较器和能力覆盖时不需要 |
| `review-pages` | 页面身份、字段别名、材料、证据、必传、规则绑定、回填策略 | 普通页面接入与字段增删改的主要入口 |
| `packages/configuration-contracts` | 两个前端之间的纯类型协议 | 仅协议变化时修改 |

页面差异由后端配置和采集清单表达，不能在前端组件中新增某个业务的审核结论。新增一种算法应扩展后端处理器与能力注册；全新的 DOM 结构或不支持的控件应扩展浏览器适配器。配置本身不能凭空产生新算法或新控件支持，不能承诺所有未来需求都只改一个 JSON。

审核图与配置图继续独立。配置 Agent 通过 `integrations/review_kernel` 调用共享配置内核；审核服务不依赖配置 Agent。保留两套独立启动入口、各自的 `.env`、日志和运行状态。

## 本轮确认并修复的问题

| 问题与根因 | 修复 | 验证依据 |
| --- | --- | --- |
| 配置工作台旧轮询覆盖新命令结果。消息和执行状态变化不一定增加草稿 revision，仅比较 revision 不足以判断新旧 | 增加读取代次，命令后的刷新使早先轮询失效 | 延迟旧轮询，在相同 revision 下返回过期完成状态，验证不会覆盖新运行状态 |
| 取消配置任务的检查与等待发生在会话锁外，后续命令可能穿插执行 | 取消检查、任务等待、会话状态更新统一持有同一会话锁 | 取消中阻塞任务清理，验证后续命令必须等待 |
| 采集快照允许重复字段/材料 ID，选中列表也允许重复；页面和材料地址缺少一致的协议检查 | 契约层拒绝重复标识、非 HTTP(S) 地址和内嵌账户凭据；保留原始签名 URL 字符串 | 非法快照返回 422 且不持久化；原有采集、会话和恢复测试继续通过 |
| 同步审核接口绕过后台任务的图片数量、重复标识/序号和地址校验 | 输入约束收敛到 `ReviewRequest.validate_images`，三个 HTTP 入口及任务管理器共用；识别源拒绝非法端口和账户凭据 | 同步、普通任务、URL 任务分别覆盖六类非法输入 |
| 二维码原图下载可被 URL 或重定向引向本机/内网；只检查字符串域名也不能阻止 DNS 重新解析变化 | 增加受控图片传输层，校验所有解析地址并固定连接 IP；每次跳转重新校验，保留原始 Host 和 TLS SNI；不同域名单独连接池；禁用环境代理绕过 | 本机、私网、元数据、IPv6、混合解析结果、恶意跳转、精确内网授权测试；真实公网 HTTPS 请求返回 200 |
| 原图限制了压缩字节数，却未限制解压像素，较小文件仍可触发大量原生内存分配 | 使用 Pillow 只读图片头，在 OpenCV 分配前限制为 2000 万像素；继续保留 8 MB 下载限制 | 修改合成 PNG 的头部为 6000×6000，确认不会进入原生解码 |
| OpenCV 解码异常不属于原有捕获类型，可能直接中断该审核步骤 | 在原生调用边界转换为受控解码失败；移除无人消费的原始异常明文字段 | 注入 OpenCV 原生异常，验证返回稳定错误码 |
| 配置试运行与正式采集的材料类型解释优先级不同，前者可能忽略图片自己的卡片标签 | 提取浏览器平台层 `material-hints.ts`，两条链路共用分类和标签/类型/槽位优先级 | 卡片为二手车发票、候选类型为登记证书时，仍按卡片声明得到发票类型；原有业务采集测试通过 |
| 配置发现只用标签名和 disabled 属性推断可编辑性，与正式采集不一致 | 复用正式采集器的可编辑判定，统一普通 readonly、禁用祖先、日期和下拉控件处理 | 发现测试覆盖普通可写及 readonly 字段；已有控件采集回归继续通过 |
| 同一页面的单字段/组合字段可并发写入，异步弹层和回滚可能互相覆盖 | 写回器以 DOM 根节点为单位锁定写入过程，冲突请求明确返回可重试错误；回填期间暂缓页面核验动作 | 并发组合/单字段测试验证无交叉写入，完成后锁释放 |
| 组合回填没有在写前验证完整字段集合和重复 DOM 控件；日期提交后关闭失败时，当前控件不在回滚列表 | 写前拒绝重复/不一致目标；已发生变更的失败控件也参与回滚 | 重复目标零写入；模拟日期已提交但弹层关闭失败，验证原值恢复且后续字段未写入 |
| HTTP 删除接口直接操作应用私有锁和图检查点；存储中保留无人调用的 `remember` 方法 | 删除生命周期收回应用服务；移除确认无调用方的存储方法和未消费的二维码异常明文字段 | 会话删除/恢复测试、Ruff、引用检查、架构检查 |
| 锁定依赖中存在已知公告漏洞 | 扩展 `brace-expansion` 升至修复版；Python `langgraph-sdk` 升至 0.4.7、`urllib3` 升至 2.8.0，更新锁文件与本地环境 | 两个 npm audit 和 Python pip-audit 复查未报告已知漏洞；本项目本身不在 PyPI，不能由依赖公告扫描代替源码审查 |
| 部分现行文档仍描述没有聊天 Agent 或需要扩展配对 | 更新文档索引与本地配置工作流，链接当前聊天配置入口 | 对照实际启动入口和配置服务实现 |
| 业务复现快照仍包含已删除 TSX 文件的摘要，未覆盖新配置程序 | 重新生成快照，扩展导出器覆盖两个前端、两个后端和共享契约 | 核对所有摘要路径存在且与当前文件内容一致 |

内网原图确有需要时，在审核后端自己的 `.env` 中显式填写 `REVIEW_IMAGE_PRIVATE_HOSTS`，使用逗号分隔的精确主机名/IP，不接受通配符或完整 URL。此设置由操作者控制，页面和模型不能扩大授权。默认留空；不需要新增登录或本机访问凭证。

## 验收边界与后续维护

自动化通过不代表所有外部业务页面均完成实页验收。真实 Chrome 页面上的第三方控件、登录态、材料 URL 有效期，以及真实模型对业务含义的理解仍应按具体页面验收；本轮没有把它们写成已验证。依赖公告扫描也不是完整安全证明。

后续新增页面优先维护一个页面版本的配置及其固定回放样例；字段增删必须同时满足证据路由、身份引用、材料依赖和已绑定规则约束。配置 Agent 的完成条件继续要求当前候选对应的浏览器试采集、独立样例回放和人工确认，模型说“完成”不能替代这些证明。

推荐继续保留 CI 中现有的 Vue/TSX 禁用检查、前后端分层检查、配置编译/回放、测试和构建门禁，避免新业务重新侵入通用主图或前端组件。
