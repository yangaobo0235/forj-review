## 后端职责整理

以下都是 `src/forj_configuration_agent` 内的后端模块，不是把业务移到前端：

- `application/service.py`：会话命令、LangGraph 节点入口和保存确认调度。
- `application/tool_execution.py`：工具预算、严格执行、结果落库及失败处理。
- `application/validation.py`：候选完成条件、试采集绑定与事实复核。
- `application/conversation.py`：持久调用身份、协议配对和业务聊天投影。
- `application/diagnostics.py`：脱敏错误记录。
- `tools/arguments.py` 与 `tools/catalog.py`：共享同一套参数模型与工具 Schema。
- `contracts/pending.py`：可区分的持久交互契约；会话状态及执行状态改为明确枚举。
- `integrations/review_kernel/library.py`：唯一审核内核适配边界，负责真实编译、回放及文件事务。

未重写审核主图。普通页面配置仍生成受控 JSON，不允许模型直接修改源码。前端新增代码仅涉及问答呈现、异常数据兜底和网络生命周期。

## 保存恢复的约束

1. 已确认且尚未对账时，仍禁止编辑、取消和删除，避免破坏可能已经写入的事务依据。
2. “继续执行”先检查原 operation_id。COMMITTED 补回执；PREPARED 恢复；ROLLED_BACK 撤销原确认。
3. 回滚后回到 DRAFTING，要求重新验证、重新确认，新保存使用新的 operation_id。
4. 保存前证据失效而尚未创建事务时，也撤销原确认，避免另一种永久锁定。
5. 发现事务外文件新增、删除或修改时，拒绝覆盖并保留 journal/marker。孤立 PREPARED 仅在正式文件与 before 完全相同时撤销。
6. SQLite 会话与文件系统仍不是一个统一 ACID 事务，通过持久日志和幂等回执对账。

## 日志

异常记录含会话/轮次、内部调用 ID、节点或工具、错误码、异常类型和最近代码位置（文件、行、函数）。不输出异常全文、完整 traceback 源码、工具参数、证件值、签名 URL 或密钥。持久失败事件补齐 call_id，便于与工具开始事件关联。
