# 车源审核功能与代码结构

本次整理覆盖材料完整性、行驶证字段核对、品牌型号补全、车型查询及规格回填。业务规则以 [车源审核](../业务/车源审核.md) 为准。

## 保留的业务约定

- 材料：行驶证正面必传；登记证书1、2页或铭牌至少一项。完整性只看上传，不受 OCR 成败影响。
- 行驶证：核对车牌、VIN、发动机号、完整车辆类型、注册日期、发证日期、所有人。使用性质和地址不核对。
- 品牌型号：保留行驶证品牌文字，用兼容的完整整车型号补全尾部。材料冲突、不确定或 VIN 不一致时禁止自动补全。发动机型号的不确定性不影响独立的品牌型号补全。
- 车型：默认使用材料中的整车型号及发动机型号，也允许人工输入。页面品牌、车系、车辆类型与两个完整型号全部取交集，不放宽后缀、不回退全库。
- 候选：完整名称、每页5条；保留同名不同 ID。必须人工选择，只有一条也不自动选择。
- 回填：按 ID 选择品牌、车系、车型，联动写入整个规格参数并逐项回读。目录缺少货箱长度时保留页面原值。
- 页面：报废置换按路径识别；其余审核按激活页签及对应面板识别。既不提交审核，也不点击下一步。

## 按功能划分的入口

| 功能 | 代码入口 | 职责 |
| --- | --- | --- |
| 车源声明 | `src/forj_review_assistant/businesses/packs/vehicle_source.py` | 材料、字段、来源、路由、可写范围、页面身份；行驶证和辅助材料字段清单各定义一次 |
| 上传完整性 | `businesses/completeness.py::evaluate_presence` | 通用上传事实与替代组判断，继续复用已有实现 |
| 材料判定 | `businesses/rules/vehicle_source_model.py` | 独立解析每组读值、检查 VIN、补全品牌型号、提供搜索默认条件 |
| 规则依赖 | `businesses/rules/catalog.py` | 明确包含 VIN 依赖，配置编译时禁止启用缺少 VIN 的车型材料规则 |
| 离线目录 | `integrations/vehicle_models.py` | 只读连接与格式检查、页面范围解析、完整性检查、精确查询、候选映射 |
| 共用车型规则 | `apps/extension/src/shared/vehicle-model.ts` | 型号规范化、查询范围校验、规格映射及配置比较；无 DOM、Chrome 和网络依赖 |
| 通信 | `platform/extension/vehicle-model-client.ts` | 侧栏搜索、原页回填、回填前目录复核及通信提示 |
| 查询会话 | `platform/extension/vehicle-model-sessions.ts` | 按源标签页保存最新可信候选，跨 worker 休眠保留会话，拒绝过期查询 |
| 搜索与候选 | `features/review/model/use-vehicle-model-search.ts` | 自动查询、手动条件、过期响应取消、分页及选择 |
| 预览与操作 | `features/review/model/use-vehicle-model-review.ts` | 规格预览、可操作原因、回填状态及结果；搜索状态和回填状态分开维护 |
| 页面写入 | `platform/browser/actions/vehicle-model-fill.ts` | 可信候选解析、范围及目录复核、控件预检、顺序写入、实际快照同步 |
| 界面 | `features/review/ui/VehicleModelPicker.vue` | 在车型字段内展示材料、条件、候选、预览与回填结果 |
| 控件适配 | `platform/browser/form-controls.ts` | 采集与回读共用完整选中名称，内部 ID 由精确选项适配单独核验 |

表内省略前缀的后端路径位于 `src/forj_review_assistant/`，扩展路径位于 `apps/extension/src/`。

## 清理和边界

删除旧的 `platform/browser/vehicle-model-catalog.ts` 混合模块，纯规则迁入 shared，Chrome 通信集中到 client；同步更新全部调用方，不保留无用转发层。删除始终返回 null 的旧一致性适配器及注册、导出，页面识别继续由实际使用的动态目录处理。历史报废兼容注册表不在本次扩大清理范围。

去掉重复的 Python 型号规范化、重复字段列表、不必要的公共导出，以及已通过身份校验之后重复执行的守卫分支。原先嵌套的材料判定不再通过修改共享 issues 列表传递结果；每组读值返回不可变结果，再明确组合品牌判定和搜索提示。辅助材料明确给出空值时不回退行驶证，原有规则保持不变。

SQLite 查询仍在同一只读事务快照内完成，保留并发配额、超时、连接释放、缺失配置检查及结果上限。页面实例、记录指纹、采集批次、当前页签、真实选项 ID 和最终回读都是有效保护，保留执行。

回填期间不能编辑、搜索或再次回填。切换车辆或重新采集立即作废旧查询及回填结果。部分写入失败时只同步实际读回值并标为未确认，不把整块规格标记为完成。查询失败会清除旧候选和选择，不留下看似仍可回填的旧结果。

## HTTP 页面回填中断修复

截图中的 `crypto.randomUUID is not a function` 来自下拉框真实 ID 校验：测试站点使用 HTTP，内容脚本中没有 `randomUUID()`，因此在选择车型之前中断。新增共用随机 ID 工具：优先使用原生 UUID，在 HTTP 环境使用 `crypto.getRandomValues()` 生成 UUIDv4；不使用非安全随机数。精确选项标记、车型查询会话和配置采集请求共用此工具。

车源继续复用报废置换的共用控件写回器：文本和数字触发原生 input/change；下拉框选择实际选项，品牌、车系、车型同时校验真实 ID；日期通过日历选择并关闭弹层。成功后滚动到可见的控件外框并高亮，不重新聚焦下拉框或日期而打开弹层。整块规格完成最终回读后，重新定位车型并高亮全部最终控件，包含原值一致的项，避免表单联动重建控件后高亮丢失。

本地复现 HTTP 下没有 `randomUUID()` 的环境，使用业务项目前端的 Vue 生产运行时与实际 Ant Select，分别选中离线车型40686和截图车型52368，9项规格均回读一致。52368对应2018款新启航版450马力，发动机型号为东风雷诺dCi450-51。缺失的货箱长度仍保留原值。另补充车源注册日期、发证日期的日历操作及定位高亮回归。

修复后扩展全量390项测试通过，类型检查、构建、lint、架构检查通过。构建产物已更新。

Chrome新标签页访问停在空白页，备用浏览器控制因无法确认当前网址而停止，本轮未完成原业务页在线验收。此次修复仅修改扩展：重新加载已构建的 `apps/extension/dist`，刷新业务页面并重新采集即可生效，无需重启审核后端。

## Chrome 脚本参数修复与浏览器模拟

后续截图出现的“车型操作失败”是另一处确定性故障：读取下拉框当前 ID 时没有目标选项，却向 `chrome.scripting.executeScript` 的 args 数组放入 `undefined`。Chrome 在执行前拒绝该参数，原有错误转换又隐藏了英文原因。现改为读取 ID 只传两个参数，选择目标时才传第三个对象；脚本调用失败会返回“读取下拉框真实选项 ID 失败”及原始原因。新增后台入口回归，校验 Chrome 不接受 undefined 参数及具体错误保留。

隔离模拟文件位于 `.tmp/model-fill-qa/`：`browser-fixture.ts` 使用业务项目相同版本的 Vue 和 Ant Select/Input/InputNumber/DatePicker 构造审核页；`qa-panel.ts` 使用实际车型字段组件及搜索、回填状态逻辑；`run-browser-workflow.mjs` 用独立 Chromium 配置目录加载实际构建的 content.js、background.js。HTTP 测试站点请求全部由本地假页面响应，不访问业务系统或数据库；车型搜索和配置复核调用本机8010服务的离线目录。

Headless Chromium 无可见侧栏，测试界面展示在扩展页面中。仅在测试副本中模拟侧栏查询消息没有 sender.tab 的特征；内容脚本来源、documentId、runtime 通信、session storage、脚本参数序列化和 MAIN world 执行均使用真实 Chromium API，生产来源校验没有放宽。测试不会提交审核、点击下一步或修改用户浏览器。

模拟时必须保持假业务页为可见标签页，贴近真实侧栏不会遮蔽业务文档的状态。若把业务页留在后台，Chromium 会暂停或节流虚拟列表的动画帧，导致测试偶发无法滚动到目标。该差异通过修正测试环境解决，没有为此更改生产选择逻辑。
