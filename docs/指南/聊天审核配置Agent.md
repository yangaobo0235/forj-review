# 本地聊天审核配置 Agent

当前代码已接入独立配置服务、持久化配置图、独立 Web 工作台和扩展采集入口。自动化验证使用脱敏页面与材料结果；当前 Chrome 真实审核页的完整操作验收仍待完成。不要把一次模型演示视为所有业务页面已验收。

## 两个前端与两个后端

| 部分 | 入口 | 职责 |
| --- | --- | --- |
| 浏览器扩展前端 | `apps/extension` | 原审核界面、页面发现与只读试采集；配置入口仅保留采集按钮 |
| 配置 Web 前端 | `apps/configuration-web`，`127.0.0.1:5174` | 页面范围选择、聊天、差异、验证、确认保存与历史恢复 |
| 审核后端 | `src/forj_review_assistant`，8010 | 实际审核与正式配置加载 |
| 配置后端 | `src/forj_configuration_agent`，8011 | 推理、会话、草稿、配置校验与受控保存 |

两个前端独立安装、构建和运行，仅共享 `packages/configuration-contracts` 的纯类型契约。Web 由独立 Vite 进程提供，通过同源代理访问配置 API，后端不托管 Web 静态资源。扩展按 Chrome 扩展生命周期运行，不需要另开 HTTP 服务。

在项目根目录执行 `uv sync --locked`，然后按需要启动：

```powershell
# 配置服务，默认 127.0.0.1:8011
.\start-configuration-local.cmd

# 审核服务，默认 127.0.0.1:8010；需要实际审核时启动
.\start-review-local.cmd

# 独立 Web 前端，默认 127.0.0.1:5174
.\start-configuration-web.cmd
```

配置服务也可直接运行 `uv run forj-configuration-agent`。原 `uv run forj-review-assistant` 保持兼容；要读取默认本地页面目录，使用新增的 `--local-pages` 参数或明确设置 `REVIEW_PAGES_DIR`。

两个脚本均从仓库根目录启动，但各自只加载自己后端包中的 `.env`：审核服务读取 `src/forj_review_assistant/.env`，配置服务读取 `src/forj_configuration_agent/.env`。首次使用将各自同目录的 `.env.example` 复制为 `.env`，分别填写 `DASHSCOPE_API_KEY` 和 `CONFIGURATION_API_KEY`。两份模板的 `REVIEW_PAGES_DIR=../../review-pages` 均解析到仓库同一目录；目录项按各自 `.env` 所在目录解析，不依赖启动工作目录。进程环境变量优先于文件。根目录 `.env` 不再自动读取，旧文件保留供自行迁移，不会自动复制或删除其中密钥。仅启动配置服务即可聊天、编辑、离线验证和保存，审核服务负责后续实际审核及生效核对。

## 首次安装与连接

1. 执行 `npm --prefix apps/extension ci` 和 `npm --prefix apps/configuration-web ci`，再执行 `npm run build:extension`。
2. 在 Chrome 扩展管理页重新加载 `apps/extension/dist` 对应的开发扩展，再刷新审核网页。新增的主机权限仅用于本地 8011 端口。
3. 启动配置服务及独立 Web 前端。在扩展进入“配置页面”，点击“采集并打开配置工作台”。
4. 扩展将字段、材料候选和页面身份保存到本地配置服务，然后自动打开 `http://127.0.0.1:5174/?capture=…`。Web 从服务读取采集结果，不通过 URL 传递完整页面数据。

更新已有安装后，需要重启配置后端以加载 `/captures` 接口，重新构建并重载扩展，再刷新业务页。Web 可独立访问 `http://127.0.0.1:5174/` 恢复已有会话；新页面采集仍从扩展开始。

本机使用无需登录、凭证或扩展配对。服务仅监听本机地址，接受 Chrome 扩展和本地 HTTP 页面的 Origin，不开放通配 CORS。旧版 `access.json` 不再读取或生成，扩展连接设置会自动移除旧凭证。扩展开发者模式无需关闭。调用模型使用各自后端 `.env` 中的模型 API Key，两服务可以填写不同密钥、端点和模型。

也可使用 IDEA 的 Python 运行配置：选择项目 `.venv` 解释器，把启动类型设为 Module name，模块填写 `uvicorn`，参数填写 `forj_configuration_agent.bootstrap.application:create_app --factory --host 127.0.0.1 --port 8011`，工作目录设为项目根目录。审核服务另建配置，模块同为 `uvicorn`，参数为 `forj_review_assistant.main:app --host 127.0.0.1 --port 8010`；在各自包下 `.env` 中设置同一个 `REVIEW_PAGES_DIR`。IDEA 环境变量仅保留 `PYTHONUNBUFFERED=1` 即可；移除之前手填的模型设置和目录覆盖值，避免它们覆盖 `.env`。无需启用 EnvFile 插件。

IDEA 的配置 Web 使用独立 npm 运行配置：选择 `apps/configuration-web/package.json`，命令 `run`、脚本 `dev`。扩展另设 npm 配置选择 `apps/extension/package.json` 的 `dev`（监听构建）或 `build`，随后在 Chrome 加载构建目录。两个前端与两个后端各自启动、停止。

两个后端的 IDEA 项目运行配置分别保存在 `.run/forj-review-assistant.run.xml` 和 `.run/forj-configuration-agent.run.xml`，直接使用 `$PROJECT_DIR$/.venv/Scripts/python.exe`，工作目录均为项目根目录，不依赖本机 SDK 的显示名称。运行和调试使用相同配置，分别监听 8010、8011；应用自己加载各自包下的 `.env`。修改项目配置文件后，必要时重新打开项目使 IDEA 加载。迁移旧本地配置时，先备份 `.idea/workspace.xml`，只移除对应的同名 Python 启动项，保留其他配置；避免在 IDE 存在尚未应用的更改时同时改写文件。

这两个 IDEA 配置均不启用 `--reload`，修改 Python 代码后手动重启，避免热更新子进程影响断点调试。需要热更新时另用项目 CLI；其 `--reload` 已限定源码范围，避免扫描整个仓库的 `node_modules`、Git 临时目录和虚拟环境。扩展不应依赖仓库根包自身，以免 npm 在 node_modules 中建立指回仓库的目录链接。无需修改 Python 标准库。

## 配置或修改页面

1. 打开实际审核详情，在扩展配置入口点击“采集并打开配置工作台”。发现过程不需要审核服务已启动，也不要求新页面先有采集清单。
2. 在新开的 Web 工作台选择待审核字段、图片样本及其中必传的材料。检查重复标签、未知控件和图片数量诊断。
3. 新页面选择“新建页面配置”；修改已有页面时，从“配置对象”选择相应页面。
4. 新建会话并描述业务要求，例如：“增加注册日期审核，使用行驶证注册日期；发动机号不再审核。”
5. 模型查询配置能力、读取材料、推理映射和编辑草稿。遇到业务歧义时回答选项或输入自然语言。
6. 出现只读试采集任务时，保持原业务标签页和记录，在 Web 中点击“执行只读试采集”。Web 委托扩展在原采集标签页执行，无需切回业务页。该操作不回填字段，不提交审批。
7. 审查验证结果、规则依据和配置差异。通过后点击“确认上述变更并保存本地版本”。
8. 保存后，等待审核服务启动，或结束现有审核作业后重启审核服务。点击“核对审核服务实际加载版本”。

前端可选环境示例为 `apps/extension/.env.example` 和 `apps/configuration-web/.env.example`，只包含 API 地址；前端不填写模型密钥。

普通配置只生成当前 `PageDefinition` 支持的 JSON，不修改前端、Python 源码或任意业务算法。新的条件必传、自定义公式、未知控件和外部集成会阻塞就绪，需要开发扩展。

保存不会热更新运行中的审核注册表。只有页面 ID、版本、有效摘要、内核兼容标识和实际加载目录全部匹配，才显示“已启用”。

## 独立验收样例

保存前需要独立样例回放，不能只靠模型说“配置完成”。示例格式见 [permit-cases.json](../示例/页面配置/回放样例/permit-cases.json)。

在“登记独立验收样例”中填写样例 ID 和 `ReplaySuite` JSON，指定候选的 `page_id`、`profile_version`、固定 `batch` 和预期。样例预期由操作人员提供；模型可以读取和执行，不能通过工具修改它。已登记 ID 不可覆盖，修改预期需登记新 ID，并重新验证。

用户登记的样例默认保存在 `.review-agent/case-sets/`，不会写进仓库示例目录。返回的 ID 形如 `local/permit-v2`，可在聊天中告诉助手。既有示例通过只读目录登记。

本版尚未提供普通业务人员使用的可视化样例标注器。没有代表性独立基准时，保留草稿并报告缺少回放依据，不自动保存未经验证的配置。

## 恢复、修改范围与回退

- 断线、关闭 Web 或重启配置后端后，通过 Web 左侧配置记录继续；必要问题保留原交互 ID。SQLite 自动兼容 v1 到 v2 的采集表迁移，不需要清空旧会话。
- 模型失败或预算耗尽，草稿保留。排除问题后点击“继续执行”。最终聊天文本与 turn 完成都不代表配置已保存。
- 已确认的保存发生中断时，点击“继续执行”，系统沿用原操作 ID 查询文件回执并对账。在对账完成前，不能修改、取消或删除此会话，以保留恢复依据。若原事务未完成，系统安全回滚并撤销原确认，草稿保留；重新验证、重新确认后用新操作保存，不需要手工删除事务日志。
- 原业务标签页关闭、重新加载、切换记录或图片 URL 过期后，从扩展重新采集；在原会话的“页面范围”中选择最近采集，点击更新当前会话现场。保留草稿和要求，旧报告及旧回执失效，需要重新核对映射。扩展仅接受本机 5174 工作台发起的受限试采集请求，并核对原标签页、页面实例和快照。
- 基础配置或模板已被另一会话修改时，当前会话拒绝覆盖；从最新正式版本新建修改会话。
- 回退时，新建会话并选择已有页面及历史目标版本；模型只核对、试采集和回放，不修改历史内容。确认后只切换 active 选择，再重启审核服务。
- 未保存会话可通过“清理此未保存会话”删除会话、事件及对应 checkpoint；包含保存回执的会话暂不删除，保留正式版本恢复依据。此功能不承诺磁盘安全擦除。

文件提交中断时，审核启动会报告 `COMMIT_INCOMPLETE`。先停止提交操作，执行：

```powershell
.\start-configuration-local.cmd --recover
```

“继续执行”也会对账本会话的原事务。CLI 恢复适用于单独排查：既能恢复带标记的未完成事务，也能发现 PREPARED 写入后尚未建立标记的孤立日志。恢复采用已记录的事务前后文件：未提交事务回退，已提交事务完成对账。发现事务之外的手工文件修改时拒绝覆盖，请先备份并人工对账。恢复完成后再恢复会话。不要手工删除事务标记来绕过启动保护。

## 设置与日志

| 设置 | 用途与默认值 |
| --- | --- |
| `REVIEW_PAGES_DIR` | 两服务共享的正式配置目录 |
| `CONFIGURATION_STATE_DIR` | 会话、checkpoint、日志与本地样例目录，默认 `.review-agent` |
| `CONFIGURATION_MODEL_ENDPOINT` | 原生工具调用兼容端点；默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`，不复用审核服务端点 |
| `CONFIGURATION_MODEL` | 会话及材料观察模型；代码默认 `qwen3.7-plus`，模板明确设置 `qwen3.8-flash` |
| `CONFIGURATION_API_KEY` | 模型凭据；只读取配置服务自己的密钥，不复用 `DASHSCOPE_API_KEY` |
| `CONFIGURATION_MAX_CALLS` | 每轮会话与材料模型请求上限，默认 24 |
| `CONFIGURATION_CASES_DIR` | 只读既有样例目录，默认 `docs/示例/页面配置` |
| `CONFIGURATION_REVIEW_URL` | 启用核对使用的审核服务地址，默认 `http://127.0.0.1:8010` |

另外设置每轮 120 次工具尝试和 900 秒执行上限。连续三次完全相同的确定性失败停止重复路径。上下文达到上限时保留草稿并中断，不丢弃要求来制造成功。

配置服务日志为 `.review-agent/configuration-agent.log`，按 5 MB 轮转，保留 5 份归档。记录进程实例、会话、轮次、revision、状态、错误码、错误类型、工具调用 ID 和代码位置；持久事件另有模型耗时、可获取的用量、工具状态及验证结果。常规日志不记录图片、完整工具载荷、证件值、签名 URL 或凭据。

审核日志继续使用原有 `REVIEW_LOG_*` 设置，详见[日志与排查](../参考/日志与排查.md)。两个进程不共用同一个轮转文件。

## 本轮可靠性修复

- 试采集证明绑定当前完整快照、草稿 revision、选择范围和候选摘要；保存前重新核对字段、控件、材料和页面身份的原始事实。旧证明缺少绑定信息时，需要重新试采集。
- 模型工具参数统一严格校验；旧版问题选项格式异常时保留自然语言回答入口。
- 已回答的澄清问题和人工答案由后端生成业务历史，刷新与重启后仍可查看。
- 工具调用使用后端内部 ID 隔离供应商 ID 的重复；同一次调用中断恢复仍保留原执行身份。
- Web 的请求超时与切换会话取消同时生效，状态轮询超时后继续重试。
- 工具执行、候选验证、协议和聊天投影拆分在配置后端包内，具体见[审查与修复记录](../参考/聊天配置Agent代码审查.md)。

## 实现与验证依据

- 配置业务位于 `src/forj_configuration_agent`，独立 CLI、app factory、状态库和配置图。
- 复用审核能力的跨包调用集中在 `integrations/review_kernel`，编译/回放公共服务位于审核包的 `runtime/configuration/service.py`，原 CLI 导出保持兼容。
- 审核图明确 `checkpointer=False`，防止在配置图内部回放时继承会话 checkpoint；审核节点拓扑未改变。
- 正式目录使用跨进程锁、待完成标记、事务日志、完整候选校验和历史快照；SQLite 和文件系统不宣称具有统一 ACID。离线编译与回放明确禁用模型初始化，不加载审核服务的 `.env`。
- 新增测试见 `tests/integration/test_configuration_agent.py`、扩展 `configuration-discovery.test.mjs`、`configuration-bridge.test.mjs` 和 Web `tests/workbench.test.mjs`。覆盖采集持久化交接、旧库迁移、原标签页绑定及错误反馈；Web 合成验收覆盖选择范围、聊天澄清和刷新恢复。
- 模型接入实际验证过原生工具往返、公共示例图片观察，以及脱敏修改任务到待确认候选。浏览器回执在该脱敏任务中由测试夹具提供，不能替代真实 Chrome 页验收。
