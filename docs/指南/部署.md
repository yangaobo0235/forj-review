# 打包与服务器部署

Windows 在项目根目录打包；Ubuntu 从发布目录启动。现有入口继续可用：

```powershell
.\package-server.cmd
.\package-extension.cmd
```

```bash
cd /home/ubuntu/review-agent-deploy
./stop-review.sh
./start-review.sh
```

普通更新可以直接执行 `./start-review.sh`，脚本会重建容器，无需先停止。原来的先停再启动方式也支持。首次更新本次脚本时，必须上传完整新版发布包并设置执行权限。

## Windows 打包

要求 Docker Desktop 的 Linux Engine 已启动、Git、Windows PowerShell 5.1 或更新版本、Node.js 22.18+。后端脚本自行在 Docker 中安装锁定的 Python 依赖，无需本机 Python。插件使用 `npm ci` 安装锁定依赖；首次安装需要网络。

| 命令 | 产物 | 用途 |
| --- | --- | --- |
| `.\package-server.cmd` | `.tmp/server-release/` | Linux amd64 后端完整发布目录 |
| `.\package-extension.cmd` | `.tmp/forj-review-extension-public.zip` | 默认连接公网后端 |
| `.\package-extension.cmd -Local` | `.tmp/forj-review-extension-local.zip` | 默认连接本机 127.0.0.1:8010 |

根目录 CMD 委托给 `scripts/release/`，从任意工作目录启动也会解析到本仓库。插件 ZIP 的根目录直接包含 `manifest.json`，另带 `.zip.sha256`。解压 ZIP 后在 Chrome 扩展管理页面选择“加载已解压的扩展程序”；替换已安装版本后，重新加载扩展并刷新业务页面。两种构建都会更新 `apps/extension/dist`，开发调试时最后执行 `-Local`。

后端发布目录包含：

```text
forj-review-api-main.tar
docker-compose.server.yml
start-review.sh
stop-review.sh
rollback-review.sh
review-common.sh
release.json
SHA256SUMS
DEPLOY.md
```

`release.json` 记录构建时间、源代码提交、是否存在未提交改动、镜像 ID 和平台；镜像中携带同一发布 ID。`SHA256SUMS` 校验镜像、配置和脚本是否来自同一发布包。构建/导出失败保留上次发布产物；不要使用失败后目录里遗留的旧包冒充本次构建。

## 上传与更新

把 `.tmp/server-release/` **里面的全部文件**上传到 `/home/ubuntu/review-agent-deploy/`，覆盖同名文件。不要只传 TAR，也不要再从旧 `.tmp/forj-review-api-main.tar` 路径取文件。传输工具使用二进制模式，不转换 Shell 文件换行符；打包脚本已统一为 LF 无 BOM。

不要上传整个 `.tmp`、本机 `.env`、`logs/` 或真实审核材料。服务器现有 `/opt/review-assistant/.env` 保留。

```bash
cd /home/ubuntu/review-agent-deploy
chmod +x start-review.sh stop-review.sh rollback-review.sh
./start-review.sh
curl --fail http://127.0.0.1:18110/health
```

脚本依次执行完整包校验、Compose 配置校验、保留上一健康版镜像与 Compose、加载镜像、准备日志目录权限、重建容器和限时健康检查。只在健康检查通过后记录成功版本。脚本使用文件锁，拒绝同时执行多项部署操作。配置检查不打印展开后的密钥。

既有安装迁移时，会优先从 `review-agent-service` 容器取得旧镜像并备份运行目录中的 Compose；找不到匹配的旧 Compose 会停止升级，要求先恢复配置，避免留下不可用的回滚。后续以 `.last-successful-image` / `.last-successful-compose.yml` 标记上一健康版；不要手工删除这些文件。

当前服务名 `review-agent`，容器名 `review-agent-service`，镜像名 `forj-review-api:main`，端口映射为 `18110:8010`。只有上传文件不会触发部署，执行启动脚本才会替换运行版本。

## 首次安装

已有服务无需重复本节。Ubuntu 安装 Docker Engine、Compose v2 插件，以及 `curl`、`flock`（util-linux）和 GNU coreutils。部署用户需要 Docker 权限。

```bash
sudo install -d -o ubuntu -g ubuntu -m 0750 /opt/review-assistant
install -d -m 0750 /home/ubuntu/review-agent-deploy
```

在服务器创建 `/opt/review-assistant/.env`，使用 `.env.example` 的变量名填写实际模型凭据。设置该文件仅部署用户可读写：

```bash
chmod 600 /opt/review-assistant/.env
```

不要在终端历史、工单或日志中粘贴密钥。必要变量是 `DASHSCOPE_API_KEY`；模型、接口地址、并发和日志参数可参考示例。并发默认 16 / 8 / 2，服务端 `.env` 可以覆盖，改完执行启动脚本使新配置生效。服务器时区通过 Compose 设为 `Asia/Shanghai`。

只读运行镜像以非 root 用户 UID 10001 启动。部署脚本使用受限的一次性容器准备 `/logs` 权限，采用应用用户属主和部署用户组，目录 2770、日志 0640，不再开放 0777。回滚到旧镜像时会读取旧镜像的实际用户 UID 并调整。不要自行对日志目录执行 `chmod 777`。

## 停止、启动、回滚

```bash
cd /home/ubuntu/review-agent-deploy
./stop-review.sh
./start-review.sh
# 升级后发现异常：恢复上一健康镜像及其 Compose
./rollback-review.sh
```

停止脚本仅停止服务，保留 `.env`、日志、镜像和回滚文件。启动脚本校验完整发布包，因此保留 TAR、`SHA256SUMS` 和其列出的全部文件。重复启动同一个镜像和配置不会覆盖上一版回滚。健康检查失败会返回非零退出码并展示最近容器日志；不会自动宣称部署成功，需要执行回滚脚本恢复。

如果失败时根本没有上一版本，无法回滚；修正配置或重新上传完整发布包后重试。不要在确认新版本稳定前执行 `docker image prune -a`，否则可能删除用于恢复的历史镜像 ID。

普通临时重启可在运行目录执行以下命令，不需要重新加载 TAR：

```bash
cd /opt/review-assistant
docker compose --env-file .env -f docker-compose.server.yml restart review-agent
```

此命令只重启既有容器，不应用 `.env` 的变更；应用配置变更使用 `start-review.sh`。

## 日志与排查

```bash
cd /home/ubuntu/review-agent-deploy
tail -f logs/review-agent.log
tail -100 deploy.log
cd /opt/review-assistant
docker compose --env-file .env -f docker-compose.server.yml ps
docker compose --env-file .env -f docker-compose.server.yml logs --tail=100 review-agent
```

应用日志按天或单文件 10 MiB 轮转，默认保留最多 30 份归档，另有当前文件；Docker 控制台最多 3 × 10 MB。`deploy.log` 单独记录部署操作，达到 5 MiB 后下一次操作轮转，保留一份归档。详情见[日志与排查](../参考/日志与排查.md)。

健康接口只检查进程能否响应，不代表模型账号或二维码官网可用；上线后还应使用非敏感样例做一次实际审核，检查模型、材料、二维码和页面写回。当前任务只完成本地构建、容器验证和部署回归，不会替你更新线上服务器。
