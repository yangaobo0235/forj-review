# 声明式页面配置

普通页面接入、字段增删、材料要求和比对来源调整，优先维护页面 JSON。系统将其编译为现有不可变 `BusinessExtensionPack` 和 `BusinessProfile`，复用现有审核引擎。这里不包含聊天、Agent、配置写入 API 或热发布功能。

本地校验、有效配置预览、版本差异、固定识别结果回放和配置快照见[本地页面配置工作流](本地页面配置工作流.md)。当前先支持本地使用，服务器公网发布另行设计。

## 职责边界

| 层 | 职责 |
| --- | --- |
| 浏览器平台 | 详情区域识别、控件与图片采集、定位、受控页面操作 |
| 前端工作台 | 展示后端任务、证据、差异区间和原因，收集审核员操作 |
| 页面配置 | 声明页面身份、采集绑定、材料、证据关系和已注册规则 |
| 后端审核 | 材料完整性、提取白名单、证据归一化与比对、政策和最终结论 |
| 后端规则目录 | 扩展特殊算法及声明它所需的字段、产出的检查项 |

后端只下发采集需要的声明给浏览器，不下发必传判定、归一化器、权威链或业务规则让浏览器执行。配置中的字段别名、区域名和控件定位参数是页面绑定元数据，实际 DOM 解析始终由浏览器完成；后端没有 DOM 操作代码。

## 使用入口

1. 参考 `docs/示例/页面配置/`，在 `review-pages/` 写入需要的配置。示例不会自动启用。
2. 校验：`uv run forj-review-assistant --check-pages review-pages`。
3. 在服务 `.env` 中设置 `REVIEW_PAGES_DIR=review-pages`，重启服务。
4. 插件重新采集页面，读取新目录和对应版本的采集清单。

目录必须存在。启动时校验整个目录，任何文件有错都会阻止启动，不会只启用一半。不要直接在生产服务的活动目录中试写草稿；先在独立目录检查，再整体替换配置并重启。

Docker 中可将目录只读挂载到 `/app/review-pages`，并设置 `REVIEW_PAGES_DIR=/app/review-pages`。随镜像交付时，将配置放入仓库 `review-pages/` 后构建。配置文件不包含真实单据值或图片地址。

## 配置契约与能力发现

- `uv run forj-review-assistant --page-schema`：输出当前 JSON Schema。
- `GET /api/review/configuration/schema`：同一份机器可读契约。
- `GET /api/review/configuration/rules`：可引用的内置规则、必要字段、检查项和执行阶段。
- `GET /api/review/page-catalog`：当前服务快照中的活动页面。

Schema 拒绝未知属性，布尔开关必须使用 JSON 的 `true`/`false`。配置不接受 Python 导入路径、JavaScript 或执行脚本。普通字段比较支持当前引擎的证据模式、已列出的归一化器、权威链和日期时效；它不是任意表达式规则语言。新增算法仍需开发后端处理器并登记到 `businesses/rules/catalog.py`。

## 新增页面

完整示例见 `docs/示例/页面配置/permit.json`。关键部分：

```json
{
  "key": "permit.vin",
  "label": "车辆识别代号",
  "aliases": ["车辆识别代号", "车架号"],
  "normalizer": "vin",
  "evidence": [{"material": "permit", "field": "license.vin"}]
}
```

这一条会同时生成页面采集定义、材料提取白名单、材料字段路由和后端字段策略。多来源时在 `evidence` 中增加条目，`mode` 缺省推导为 `PARALLEL`。`evidence` 是此字段的完整来源列表，显式修改它时会替换此字段原有路由。

- `key` 是稳定领域标识；中文改名只改 `label`、`aliases` 等页面绑定。
- 需要页面取值的字段必须声明 `aliases`；`locator_id`/`locator_name` 只是附加定位条件。材料内部字段可设置 `page_evidence_required=false`，规则内部输入不要求页面别名。
- `evidence.field` 是材料模型提取的字段名，允许与领域 `key` 不同。
- 一个材料分区时 `evidence.scope` 可省略；多个分区时必须明确指定。
- `sections` 描述页面字段区块；`page_groups` 描述图片区域，二者不混用。
- 新材料在 `materials` 声明名称、关键词、读取指引即可，无需更新前端材料类型表。
- 材料 `required=true` 表示必传；相同 `alternative_group` 表示组内任一材料满足即可。
- `required_pages` 会自动加入页码提取；页码字段使用现有识别协议的 `registration.covered_pages`，不要求材料一定是登记证。
- `extra_fields` 仅补充供专用处理器读取的材料字段；普通审核字段无需重复填写。
- `remove_extra_fields` 删除显式补充的提取字段；普通字段来源和页码要求变更后，其自动提取项会重新计算。
- `remove_materials` 删除继承材料及其必传要求，但必须显式更新仍引用该材料的字段、权威链或证据要求。
- 配置不控制模型任意生成审核结论；模型提取原始信息，后端按声明执行比对。

新配置默认不启用页面写回。确有需要时，声明已支持的 `page_actions`、`writable_control_kinds`（`text`、`textarea`、`number`、`select`、`date`）、逐字段 `writable`、`identity_anchors` 和独立 `record_identity_fields`。浏览器仍执行记录身份、控件和回读检查；仅声明 writable 不会绕过这些检查。

控件类型表示逻辑类型：Ant Design 单日期选择器内部即使是只读文本输入，也按 `date` 采集和回填，通过日历提交日期。下拉框按页面选项文本精确匹配。控件适配属于扩展的浏览器平台层，业务配置只声明允许回填的字段和类型。日期范围、时间选择及未适配的自定义控件交人工处理，详见[页面控件回填排查](../参考/页面控件回填排查.md)。

## 修改已有业务

参考 `vehicle-source-v2.json`，使用精确模板：

```json
"extends": {"page_id": "vehicle_source:default", "version": "1.0"},
"fields": [{"key": "vehicle.issue_date", "max_age_days": 180}]
```

继承时，未填写的属性保留原值。示例仅改变日期时效，原字段别名、材料来源、写回边界及其他字段均保留。材料也支持局部修改名称、关键词或必传属性。模板可以是内置业务，也可以是同目录另一个配置版本；加载器按依赖顺序编译，不依赖文件名先后。

新增字段：在 `fields` 增加带 `label` 和 `evidence` 的条目。删除字段：使用 `remove_fields`。删除时清理该字段的路由和展示绑定；如果仍被身份锚点、组合字段、材料证据要求或业务规则引用，则明确报错。应更新相关配置或显式停用依赖规则，不能因删除一个字段就默认停用整项审核。

`enable_rules`/`disable_rules` 只控制已注册的业务规则。对继承后的全部字段检查绑定校验生产者，停用规则后需显式清理或替换相关 `checks`；必审字段不能仅剩一个失效绑定。地区政策随模板继承，并与新配置版本对齐；不支持通过单独停用政策能力绕过政策声明。特殊主体类型和挂靠任务由字段的受限 `task_projector` 选择后端实现，不向前端下发审核算法。

## 版本、生效与回退

配置身份是 `page_id + version`，不能覆盖同身份版本。同一快照内拒绝重复身份；使用 `--snapshot-pages` 建立本地历史后，也拒绝跨重启覆盖已记录版本的源内容或有效配置，`active` 切换不受此限制。同一 `page_id` 的业务和地区不能跨版本改变；接入另一业务或地区应使用新页面身份。修改内置 `1.0` 配置时使用新版本，例如 `2.0`。同一个 `page_id` 只允许一个外部配置版本标记 `active=true`；旧版本可设为 `active=false` 并继续作为模板或历史请求的解析目标。

活动版本用于页面识别目录，采集清单和审核请求携带精确页面与版本。服务运行期间整个注册表保持不变，采集配置不可用时，插件阻止已配置页面进入审核，避免用旧内置规则继续执行。多页面查询不明确时接口返回 409，不取列表末尾猜一个。

回退：将旧配置改为活动版本、新配置改为非活动版本，校验后重启；回退到内置业务时，可移除该页面的外部活动版本。重启不保留内存中的审核作业，应先等待当前作业结束。

## 支持范围

页面必须能由现有浏览器采集器读取。普通表单、区域和图片分组可以通过元数据配置；特殊 iframe、自定义绘制控件等需要开发人员扩展浏览器通用采集能力。本轮没有实现未知页面探查 UI、聊天澄清、自动编辑文件或在线发布，这些可在此配置契约之上继续建设。


## 审核判定边界

配置 Agent 通过能力目录的 `decision_policy` 读取统一红橙绿语义，具体见[字段与判定规则](../概念/字段与判定规则.md#判断语义)。`uncertain_requires_review` 必须为 `true`；配置不能将不确定材料直接判通过或冲突。既有政策人工例外仍交人工确认。新配置验证、离线回放与实际审核使用同一内核。

回放样例可增加 `expect.comparison_reasons`、`expect.check_reasons`，例如 `"comparison_reasons": {"permit.vin": ["RECOGNITION_UNCERTAIN"]}`，用于区别识别不确定和缺少材料。未填写这两项的既有回放样例仍兼容。
