# 项目结构与迁移

项目名为 `forj-review-assistant`，Python 包为 `forj_review_assistant`，扩展 npm 包为 `@forj/review-extension`。浏览器里沿用“赋界审核助手”品牌和原有权限。

## 目录与职责

```text
forj-review-assistant/
├── src/forj_review_assistant/
│   ├── interfaces/          # HTTP、命令行入口
│   ├── bootstrap/           # 应用创建、服务装配与关闭
│   ├── config/              # 环境文件与模型连接配置
│   ├── contracts/           # 请求、响应、证据和识别数据模型
│   ├── businesses/          # 业务声明、地区配置和业务规则
│   │   ├── configuration/  # 页面配置 Schema、编译与快照加载
│   │   ├── packs/          # 原生声明与统一运行时模型
│   │   └── rules/          # 业务处理器及 catalog.py 装配目录
│   ├── capabilities/        # 能力注册与通用子图
│   ├── runtime/             # 工作流、任务与公平调度
│   ├── evidence/            # 字段归一化、证据比较和聚合
│   ├── presentation/        # 审核任务、建议和响应装配
│   ├── integrations/        # 模型识别、二维码与官网适配
│   └── observability/       # 日志配置
├── apps/extension/
│   └── src/
│       ├── app/             # 侧栏装配与全局样式
│       ├── entrypoints/     # Content Script 与后台入口
│       ├── features/review/ # api、model、presentation、ui
│       ├── platform/        # browser、extension
│       └── shared/          # 跨模块契约
├── tests/                   # unit、contracts、integration、tooling
├── review-pages/            # 声明式页面配置交付目录
├── scripts/                 # dev、ci、release
├── deploy/                  # Dockerfile 和服务器运维脚本
├── docs/
├── pyproject.toml
└── package.json
```

Python 使用标准 src 布局，根目录统一管理依赖和测试。沿用 Pico 的职责分离原则，同时保留审核产品的业务、证据和呈现模块。

业务底座沿用这些职责目录，局部增加配置编译与规则目录即可，无需整体搬迁。普通页面接入和字段增删见[声明式页面配置](声明式页面配置.md)，耦合与遗留清理依据见[业务底座审计](../参考/业务底座改造与遗留审计.md)。

Python 文件使用 snake_case，React 组件使用 PascalCase，普通 TypeScript 文件和目录使用 kebab-case。辅助函数首先留在拥有该职责的模块。

## 依赖边界

- `contracts`、`config` 不导入执行器、业务、HTTP 或装配层。
- 业务、证据和能力模块不导入 HTTP、装配、任务运行时或具体外部客户端。
- 外部集成不反向依赖运行时、HTTP 或呈现层。
- 前端 `shared` 不依赖功能或平台；`platform` 不依赖 React 或审核界面；功能不反向依赖入口。
- 产品源码不导入测试与仓库脚本。

使用 `uv run python scripts/ci/check_architecture.py` 和 `node scripts/ci/check-extension-architecture.mjs` 检查，均已接入 CI。动态注册与交互行为由回归测试覆盖。

## 本地升级

1. 停止旧开发服务，从仓库根目录运行 `uv sync --locked`，重新建立根目录 `.venv`。
2. 将旧 `review-agent-service/.env` 的配置迁到根目录 `.env`，不得用示例覆盖已有配置。进程环境变量仍优先。
3. 运行 `npm --prefix apps/extension ci`，构建后加载 `apps/extension/dist`，刷新审核网页以更新 Content Script。
4. 运行 `uv run forj-review-assistant --reload`，或 `scripts/dev/start-agent.ps1`。日志相对路径现在从仓库根目录计算，默认本地目录为 `logs/`。
5. IDE Python 源码目录改为 `src`，解释器改为根目录 `.venv`，测试入口改为根目录 `tests`。

项目的磁盘目录统一使用 `forj-review-assistant`，本机路径为 `D:\fjkj\software\workspace\forj-review-assistant`。IDE 和终端应从这个目录重新打开项目。

本次已迁入全部项目文件并逐文件核对 SHA-256，Git 完整性检查通过。原 `review-assistant` 路径只剩被 Qoder 和当前 Codex 会话占用的空目录，关闭旧窗口后即可移除；新项目不依赖该空目录。

本地清理包含旧 `review-agent-service/`、`review-extension/`、迁移中间目录、临时备份、日志、IDE 状态、虚拟环境、依赖安装目录和构建缓存；保留产品源码、Git 历史及根目录 `.env`。旧环境配置中的有效项已在根目录配置中，另有 4 项退役功能配置不再使用。需要运行时，先执行 `uv sync --locked` 和 `npm --prefix apps/extension ci`，再启动服务或构建扩展。这些命令生成的环境和产物继续由 `.gitignore` 排除。

## 部署与回滚

镜像为 `forj-review-api:main`，TAR 为 `forj-review-api-main.tar`，构建上下文为仓库根目录：

```powershell
docker build -f deploy/Dockerfile -t forj-review-api:main .
```

Compose 服务键 `review-agent`、容器名 `review-agent-service`、端口和服务器目录继续沿用既有部署标识，避免产生第二个容器或丢失配置。首次升级前，将服务器原 `review-agent-service/.env` 复制到运行目录根下 `.env`，保留旧文件。

部署脚本在首次升级时也会把旧 `review-agent-service:main` 镜像保存为 `forj-review-api:rollback`。HTTP 路径、协议 2.0、业务版本、页面动作 ID 和扩展消息名称保持原有含义，无需审核数据迁移。详见[部署指南](部署.md)。
