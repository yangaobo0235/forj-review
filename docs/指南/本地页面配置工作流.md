# 本地页面配置工作流

当前先在本地编写、验证和使用页面配置。这里没有服务器发布、远程配置写接口、自动发布或聊天 Agent；所有工具复用当前配置编译器和审核主图。

## 普通业务改哪里

普通页面在 `review-pages/` 维护 JSON。页面取值字段同时声明 `aliases` 和 `evidence`；标签、来源、时效、必传材料等优先修改声明，不需要修改前端或复制主图。

- 页面字段必须有别名。`locator_id`、`locator_name` 是缩小定位范围的条件，不能代替别名；材料内部字段可显式设置 `page_evidence_required=false`。
- 材料内部字段无需页面值也可完成材料核验，结果会保留在工作台中；同一页面上其他要求页面取值的字段仍按各自配置校验。
- `evidence` 是字段的完整来源列表。修改后只从当前有效路由生成提取字段，连续继承不会累积旧来源。
- `remove_fields` 删除字段及其路由和检查绑定；仍被身份、组合字段或规则引用时拒绝通过。
- `remove_materials` 删除继承的材料和必传要求；仍有字段、权威链、证据路由或材料证据要求引用时必须先修改引用。
- `materials[].extra_fields` 增加处理器专用提取输入，`remove_extra_fields` 删除此前显式保留的输入；普通字段的提取项始终由路由生成。
- 停用规则后，继承的检查绑定也必须有生产者。可以显式清空相关字段的 `checks`，或改绑已启用的规则；必审字段还必须保留有效审核依据。

例如，停用车源车型规则时，必须同时清理其投影字段的绑定，不能留下失效引用：

```json
{
  "disable_rules": ["vehicle_model_consistency"],
  "fields": [{"key": "vehicle.model", "checks": []}]
}
```

这是配置片段，仍需与页面身份、版本、模板等属性一起使用。若要删除该字段，应使用 `remove_fields`；清空 checks 不代表把必审要求自动取消。

## 校验与查看实际结果

在仓库根目录执行：

```powershell
uv run forj-review-assistant --check-pages review-pages
uv run forj-review-assistant --check-pages review-pages --json
uv run forj-review-assistant --inspect-pages review-pages
```

校验同时装配运行时能力，检查未知规则、无效依赖及不合法的证据阶段。`--json` 将失败输出为含 `ok=false`、`errors` 的 JSON，退出码为 2。

`--inspect-pages` 输出继承展开后的字段、材料提取清单、路由、检查绑定、能力、页面元数据和配置 SHA-256。输出同时包含内置页面与外部配置，并标记活动版本。它只读取配置，不写文件、不调用模型、不访问审核页面。

比较两个独立目录中的活动页面：

```powershell
uv run forj-review-assistant --compare-pages .tmp/pages-before .tmp/pages-after
```

按稳定 `page_id` 对齐，即使版本从 `1.0` 变成 `2.0`，仍能看到具体字段、材料、检查和能力的新增、删除和变化。非活动版本的完整内容仍可分别通过 `--inspect-pages` 检查。

## 离线回放

回放文件放在页面配置目录的子目录或独立测试目录，不要与根目录的页面 `.json` 混放。公开示例只使用虚构值和 `example.test` 图片地址：

```powershell
uv run forj-review-assistant --replay-pages docs/示例/页面配置 --cases docs/示例/页面配置/回放样例/permit-cases.json
```

示例覆盖一致、冲突、缺失材料和不确定证据。回放使用真实主图，必须提供固定 `batch`，不会调用模型、读取图片 URL 或执行官网核验；外部核验只能消费 `external_results` 固定样例，没有样例时生成证据不足结果。

每项用例包含：

| 属性 | 用途 |
| --- | --- |
| `name` | 不重复的样例名称 |
| `request` | 固定页面身份、版本及脱敏页面采集结果 |
| `batch` | 固定材料识别、字段观察及不确定标记 |
| `external_results` | 按能力 ID 提供固定 `checks`、`qr_checks`、`evidence`，可省略 |
| `expect.recommendation` | 必填整单预期 |
| `expect.comparisons` / `expect.checks` | 指定字段或检查的预期状态 |
| `expect.capabilities` | 核对能力执行、跳过、阻塞或失败状态 |
| `expect.comparison_fields` | 精确核对比较字段集合，防止少审核一项 |
| `expect.manifest_fields` | 精确核对浏览器应采集的字段集合 |
| `expect.task_fields` / `expect.writable_fields` | 精确核对任务目标及允许写回的字段集合 |

回放通过退出码为 0，预期不符为 1，文件或配置无效为 2。报告只列标识、状态、摘要和预期差异，不回显页面值或材料原文。DOM 控件是否真实存在仍由浏览器采集验证；固定 batch 回放不能代替真实页面验收。

## 本地快照、版本保护与回退

完成检查与回放后，可为当前本地配置建立基线：

```powershell
uv run forj-review-assistant --snapshot-pages review-pages
```

命令在 `review-pages/.history/` 写入内容寻址的配置快照和 `versions.json` 索引。源文件与继承展开结果都记录摘要。后续校验、检查及服务启动会拒绝同一 `page_id + version` 的内容或模板发生改变，要求使用新版本。即使文件被删除后重新建立，索引仍保留已记录版本的约束。

这是显式建立的本地基线；尚未保存快照的草稿允许修改。目录整体复制时应保留 `.history/`。快照不保存真实页面数据、图片或审核结果，不负责恢复内存中的审核作业。

`active` 属于本地版本选择，不计入不可变源配置摘要。新增版本时把旧版本设为 `active=false`，新版本设为 `active=true`，保留精确模板文件；验证后重启本地后端并重新采集。需要回退时交换活动标记，校验并重启即可。若工作文件丢失，可从快照的 `files` 对象恢复原文件；不要手工篡改历史摘要。

快照写入使用独占写锁和原子替换索引。若本地进程异常退出留下 `.history/write.lock`，先确认没有其他快照命令运行，再清理该锁文件。读取检查不会创建或改写历史。

## 在本地服务中使用

在本地 `.env` 设置：

```dotenv
REVIEW_PAGES_DIR=review-pages
```

服务启动时整体加载配置；编辑文件不会热更新。配置错误时启动失败，不会启用半份配置。重启前结束当前审核作业，启动后插件重新采集，读取活动版本的目录与精确清单。

审核日志新增 `review configuration` 事件，记录页面 ID、配置版本和 `configuration_sha256`，可以与预览及回放报告对账；不记录配置中的真实审核输入。

未来配置 Agent 可以调用同样的 Schema、校验、预览、差异和回放入口来准备修改。本轮没有实现聊天、自动写配置或服务器公网发布。
